준현 헬퍼 v1.3.4 — Windows x64

실행 방법
1. 받은 ZIP 파일을 원하는 폴더에 압축 해제합니다.
2. '준현 헬퍼.exe'를 실행합니다.
3. 처음 실행하면 프로필을 만들고 필요한 최신 게임 데이터를 온라인에서 내려받습니다.
4. 프로그램 실행 시 GitHub의 최신 정식 준현 헬퍼 릴리즈를 확인합니다. 더 최신 버전이 있으면 업데이트 여부를 묻습니다.

v1.3.4 주요 변경 — Scanner 실전 인식 결합 하드닝
- 실제 인게임 피드백에서 반복된 `Esma「ch` 형태의 OCR 오류를 특정 문자로 임의 치환하지 않고, 현재 공식 카탈로그 전체에서 정확히 한 글자 위치만 미상인 패턴이 유일하게 성립할 때만 복구합니다.
- 현재 공식 아이템명과 같은 길이/같은 나머지 글자 구조를 요구하고, 후보가 둘 이상이거나 2순위 margin이 부족하면 기존 원칙대로 식별하지 않습니다.
- 돋보기는 일반 밝은 컴포넌트 경쟁이 아니라 실제 상세창 상단 프레임 좌측의 고정 search-icon lane 안에서 정규화된 ring/빈 중심/우하단 handle template으로 확인합니다.
- 제목 글자가 돋보기처럼 보여도 search-icon lane 밖이면 돋보기 후보가 될 수 없습니다.
- 빨간 닫기 X도 red box 위치만 보지 않고 X 대각선 형태를 포함한 template evidence를 사용합니다.
- `HEADER_FRAME_LOCKED`를 완전히 통과하지 못한 structural 후보는 OCR 후보에서 제거합니다.
- 상세창 초록 영역은 확정된 돋보기/X/header 위치에서 상단·좌우 경계를 다시 정렬하여 초기 geometry drift를 그대로 표시하지 않습니다.
- '인식 이미지'에서 저장하는 PNG에는 실제 캡처 픽셀 위에 초록=상세창, 파랑=제목 ROI, 노랑=돋보기, 빨강=닫기 X 진단 박스를 합성합니다. 문제 피드백 시 저장 PNG만으로 검출 좌표를 확인할 수 있습니다.
- 기존 confidence 기준, 일반 fuzzy 기준, top1/top2 margin, bounded one-edit 안전 조건은 완화하지 않았습니다.
- 최고 상점가, 플리마켓 평균가, 필요한 개수(RequiredTotal)의 의미와 데이터 연결은 변경하지 않았습니다.
- Game Content schema, user.db schema, Scanner display settings schema는 변경하지 않았습니다.

v1.3.3 주요 변경 — 실제 상세창 헤더 기준 Scanner 회귀 수정
- v1.3.2에서 사용자가 명시적으로 신고했던 돋보기/제목 시작점 문제가 실제 게임에서 재발한 원인을 전체 인식 경로 기준으로 수정했습니다.
- 12장의 실제 2048x1280 인식 원본에서 반복 확인된 긴 회색 상단 프레임, 빨간 X, 프레임 좌측의 13x13 돋보기 밝은 코어를 authoritative anchor로 사용합니다.
- 아이템 이름의 첫 글자 컴포넌트는 더 이상 제목 ROI의 왼쪽 경계를 결정하지 않습니다. 한글 글자 분할 때문에 제목 앞부분이 잘리는 회귀를 차단합니다.
- 빨간 X + 상단 프레임 + 고정 아이콘 레인 + 돋보기 + 어두운 제목 필드가 함께 잠기기 전에는 OCR/아이템 확정을 실행하지 않습니다.
- `「` 같은 현재 공식 카탈로그 외 기호는 matcher 입력에서 제거되며, 인식 이미지 진단에서는 원본 OCR과 정리 후 matcher 입력을 서로 다른 값으로 표시합니다.
- 기존 confidence 기준을 낮추지 않았고, 1-edit 복구의 전체 카탈로그 유일성 및 10%p 2순위 margin도 유지합니다.
- 최고 상점가, 플리마켓 평균가, 필요한 개수(RequiredTotal)의 의미와 데이터 연결은 변경하지 않았습니다.
- Game Content schema, user.db schema, Scanner display settings schema는 변경하지 않았습니다.

v1.3.2 주요 변경 — Scanner 실전 OCR 실패 보강
- 실제 인게임/DisplayTest 사례에서 돋보기 아이콘이 존재해도 주변 글자 분할 조건 때문에 anchor 후보가 버려지는 문제를 수정했습니다.
- 돋보기는 좌측 헤더 위치, 밝은 링, 내부 빈 공간, 우하단 손잡이 형태를 핵심 evidence로 사용하고 뒤따르는 글자 evidence는 보조 조건으로 사용합니다.
- 현재 공식 한국어 아이템 카탈로그에서 실제로 사용되는 문장부호/기호만 허용 목록으로 자동 파생합니다. OCR이 만든 `, 「 같은 카탈로그 외 기호는 아이템명 매칭 전에 제거합니다.
- 중간 길이 제목에서 정확히 한 글자 누락/치환 때문에 기존 퍼센트 기준을 약간 밑도는 경우를 위한 제한적 1-edit 복구를 추가했습니다.
- 1-edit 복구는 전체 현재 공식 카탈로그에서 후보가 유일하고 2순위와 최소 10% 이상 벌어질 때만 허용합니다. 전역 confidence 기준 자체는 낮추지 않았습니다.
- 'Thermite 테르밋' → 'Themite 테르밋' 같은 단일 누락은 안전 조건을 충족하면 복구할 수 있습니다.
- 'Gunpowder "Eagle" 화약'처럼 여러 글자가 동시에 틀린 저신뢰 OCR은 퍼센트만으로 확정하지 않고 기존 Tarkov 폰트 기반 시각 검증이 충분할 때만 복구합니다.
- 최고 상점가, 플리마켓 평균가, 필요한 개수(RequiredTotal)의 의미와 데이터 연결은 변경하지 않았습니다.
- Game Content schema, user.db schema, Scanner display settings schema는 변경하지 않았습니다.

v1.3.1 주요 변경 — Scanner 상세창 제목 인식 강화
- 상세창 제목을 좌측 밝은 컴포넌트 하나로 추정하지 않고, 어두운 제목 필드·좌측 돋보기·첫 글자군·우측 빨간 X를 함께 구조적으로 확인합니다.
- 상세창 좌측 좌표가 일부 어긋나도 실제 돋보기를 왼쪽 확장 영역에서 다시 찾고, 첫 한글 글자가 돋보기로 오인되어 잘리는 경우를 방지합니다.
- 돋보기 후보는 위치/크기/비율뿐 아니라 내부 빈 공간, 둘레, 우하단 손잡이, 뒤따르는 글자 evidence를 함께 평가합니다.
- OCR이 공식 아이템명으로 통과한 경우에도 로컬 Tarkov 제목 폰트와 현재 공식 아이템 카탈로그를 이용한 보수적 시각 corroboration을 수행할 수 있습니다.
- 시각 evidence가 엄격한 기준으로 다른 공식 Item ID를 명확하게 지목하는 경우에만 OCR identity를 교정합니다. 시각 검증이 불가능하거나 애매하면 기존 OCR 성공을 임의로 버리지 않습니다.
- 프로그램 상단 상태 텍스트 왼쪽에 실행 중인 EXE의 실제 버전이 표시됩니다.
- 최고 상점가, 플리마켓 평균가, 필요한 개수(RequiredTotal) 계산 의미와 Scanner 표시 설정 schema는 변경하지 않았습니다.
- Game Content schema와 user.db schema는 변경하지 않았습니다.

v1.3.0에서 추가된 Scanner 분석·단축키 워크플로
- Scanner의 최신 인식 원본 이미지를 사용자가 원하는 위치에 PNG로 저장할 수 있습니다. v1.3.4부터 저장 PNG에는 분석용 진단 사각형이 함께 합성됩니다.
- 모든 연결 디스플레이를 기존 테스트 인식 파이프라인으로 한 번만 검사하는 '1회 테스트 스캔'을 사용할 수 있습니다.
- 1회 인게임 스캔, 1회 테스트 스캔, Scanner ON/OFF를 각각 전역 단축키로 사용할 수 있습니다.
- 기본 단축키는 순서대로 Ctrl+Shift+F10, Ctrl+Shift+F11, Ctrl+Shift+F12입니다.
- Scanner 탭의 '단축키 설정'에서 세 단축키를 각각 변경하거나 사용하지 않도록 설정할 수 있습니다.
- 같은 단축키를 두 Scanner 명령에 동시에 지정할 수 없습니다.
- 1회 인게임/테스트 스캔은 버튼이 아니라 단축키로 실행합니다.
- v1.2.x에서 변경해 둔 기존 1회 스캔 단축키는 인게임 1회 스캔 단축키로 우선 보존합니다.

Scanner 사용
- '스캐너'는 EscapeFromTarkov 게임 창의 Borderless client-area를 실시간 감지합니다.
- '테스트'는 연결된 전체 디스플레이에 같은 인식 파이프라인을 적용합니다. 실사용 Scanner와 동시에 켤 수 없습니다.
- 1회 인게임 스캔은 현재 Tarkov 화면을 한 번 정밀 분석합니다. 기본 단축키는 Ctrl+Shift+F10입니다.
- 1회 테스트 스캔은 모든 연결 디스플레이를 한 번만 정밀 분석합니다. 기본 단축키는 Ctrl+Shift+F11입니다.
- Scanner ON/OFF 단축키의 기본값은 Ctrl+Shift+F12입니다.
- 세 전역 단축키는 Scanner 탭을 보고 있지 않아도 준현 헬퍼가 실행 중이면 사용할 수 있습니다.
- '아이템 목록 최신화'는 현재 GameMode의 공식 한국어 전체 아이템 카탈로그를 갱신합니다.
- '인식 이미지'는 최신 캡처 한 장과 상세창/제목 ROI, anchor, 원본 OCR, 정리 후 matcher 입력 및 최종 판단을 확인하는 진단 기능입니다.
- 인식 이미지는 기본적으로 메모리에만 유지되며 '이미지 저장'을 선택했을 때만 사용자가 지정한 PNG 파일로 저장됩니다. 저장 PNG에는 초록=상세창, 파랑=제목 ROI, 노랑=돋보기, 빨강=닫기 X 박스가 포함됩니다.
- '로그 삭제'는 최근 인식 기록, %LocalAppData%\JunhyunHelper\logs\scanner.log(.1), 최신 메모리 인식 이미지를 정리합니다. 사용자가 별도로 저장한 PNG 파일은 삭제하지 않습니다.

Scanner 표시 데이터
- 최고 상점가: fleaMarket을 제외한 유효 판매처의 RUB 환산 가격 중 최댓값
- 플리마켓 평균가: positive avg24hPrice
- 상인/플리 가격·슬롯: 유효한 width × height 슬롯 수 기준
- 필요한 개수: 현재 Needed Items 계획의 RequiredTotal. 보유 Inventory를 뺀 부족량이 아닙니다.
- 가격이나 크기 정보가 누락되면 해당 표시 필드만 비우고 Item ID 식별 자체를 버리지 않습니다.

Scanner 인식 원칙
- 현재 공식 한국어 전체 아이템 카탈로그가 Item identity의 권위입니다.
- 상세창 제목 ROI의 수평 경계는 실제 상단 프레임·빨간 X·고정 검색 아이콘 레인·돋보기로 확정하며 첫 글자 컴포넌트가 왼쪽 경계를 결정하지 않습니다.
- 돋보기와 닫기 X는 고정 위치 geometry뿐 아니라 정규화된 icon-shape template evidence를 함께 사용합니다.
- 필수 header anchor를 모두 잠그지 못하면 OCR을 실행하지 않고 식별을 보류합니다.
- Windows ko-KR OCR이 primary text recognizer입니다.
- OCR 텍스트는 current official catalog에서 실제 사용되는 문자/기호 정책으로 정리한 뒤 matcher에 전달합니다.
- 영숫자 사이에서 카탈로그 밖 기호가 한 글자처럼 나타난 경우 그 문자를 임의 추정하지 않고 '?' 형태의 one-unknown-glyph evidence를 별도로 유지합니다. 전체 현재 공식 카탈로그에서 유일하고 충분히 분리된 후보일 때만 복구합니다.
- 정확히 한 글자 오류를 복구하는 기존 1-edit 예외 경로도 current catalog 전체에서 유일한 후보이며 충분한 2순위 margin이 있을 때만 사용합니다.
- OCR 성공/실패 모두에서 필요한 경우 로컬 Tarkov 제목 폰트 기반의 보수적 시각 검증/복구를 사용할 수 있습니다.
- confidence와 1·2순위 차이가 부족하면 Item ID를 확정하지 않습니다.
- 실제 스캔 순간에는 외부 API를 호출하지 않고, 아이콘도 새로 다운로드하지 않습니다.
- 게임 메모리 읽기, DLL injection, 패킷 가로채기를 사용하지 않습니다.

사용자 데이터
- 사용자 데이터는 프로그램 폴더가 아니라 %LocalAppData%\JunhyunHelper 에 저장됩니다.
- 프로그램 업데이트는 user.db, Game Content cache, 이미지 cache, Map/Ammo/Scanner 사용자 설정과 Scanner 로그를 교체하지 않습니다.
