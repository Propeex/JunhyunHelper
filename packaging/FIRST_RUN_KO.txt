준현 헬퍼 v0.1.11 — Windows x64

실행 방법
1. 받은 ZIP 파일을 원하는 폴더에 압축 해제합니다.
2. '준현 헬퍼.exe'를 실행합니다.
3. 처음 실행하면 프로필을 만들고 필요한 최신 게임 데이터를 온라인에서 내려받습니다.

배포 형태
- 설치 프로그램이 필요 없는 portable/self-contained Windows x64 빌드입니다.
- .NET/WPF/SQLite/Skia 런타임은 '준현 헬퍼.exe'에 포함됩니다.
- 지도 시스템이 경로로 직접 읽는 검증된 파일만 Assets 폴더에 둡니다.
- 실행 폴더 루트에는 '준현 헬퍼.exe', 이 안내문, Assets 폴더만 두는 것을 기준으로 합니다.
- 별도 .NET 설치나 관리자 권한은 필요하지 않습니다.
- 코드 서명이 되어 있지 않아 Windows SmartScreen 경고가 표시될 수 있습니다.

사용자 데이터
- 사용자 진행 데이터: %LocalAppData%\JunhyunHelper\user.db
- 게임 데이터: %LocalAppData%\JunhyunHelper\content
- 이미지 캐시: %LocalAppData%\JunhyunHelper\image-cache
- 지도 제품 설정: %LocalAppData%\JunhyunHelper\map-product-settings.json
- 탄약 즐겨찾기: %LocalAppData%\JunhyunHelper\ammo-favorites.json
- 프로그램 로그: %LocalAppData%\JunhyunHelper\Logs
- v0.1.10에서 v0.1.11로 교체해도 기존 Profile / Quest / Inventory / Hideout / Map 설정은 유지됩니다.

v0.1.11 주요 변경
- v0.1.10에서 실행 중 visual tree 후처리로 처리되어 실제 화면에 안정적으로 반영되지 않던 UI 변경을 원본 UI 구조에 직접 적용했습니다.
- 유동 제출 아이템 행 자체를 68px 행 / 44px 아이콘 구조로 만들고, 아이콘 + 이름/분류는 좌측, 인레이드/일반 보유량은 우측 고정 영역에 배치했습니다.
- 유동 제출의 36px 아이콘 프레임 후처리 코드를 제거해 아이콘 clipping과 레이아웃 재생성 시 원상복귀 가능성을 없앴습니다.
- 탄약 탭 XAML에서 중복 '구경', '즐겨찾기' 라벨을 제거하고 구경 선택 박스와 즐겨찾기 선택 영역 폭을 직접 고정했습니다.
- 탄약 즐겨찾기 버튼은 ☆/★만 표시하며, 즐겨찾기 목록 선택 버튼은 별도로 유지합니다.
- 탄약 상세정보 접기/펼치기 버튼과 상세정보 host를 원본 XAML에 직접 배치해 중앙 정렬 상태가 항상 유지되도록 했습니다.
- 지도 진행 중 Quest 목록을 생성할 때부터 checkbox / A·B·C marker / Quest 이름을 독립된 고정 열로 만들고, Quest 이름은 marker 바로 뒤에서 좌측 정렬됩니다.
- 기존 runtime visual-tree polish bridge는 제거했습니다.
- v0.1.10에서 해결된 EFT 1.1 trader task-pool LL1 초기 상태 판정과 Quest '확인 필요' 개선은 그대로 유지합니다.

퀘스트 판정 기준
- 서로 다른 taskRequirements는 AND, 한 requirement의 status[]는 OR입니다.
- 별도 '수주 가능' 상태를 만들지 않으며 게임에서 받을 수 있는 Quest는 Helper에서 즉시 수락한 것으로 간주합니다.
- source가 직접 제공한 prerequisite 의미를 우선하며 BTR Driver / Ref / Lightkeeper 특수 규칙도 기존 검증 정책을 유지합니다.
- 2026-08-17 live 데이터의 검증된 dialogue Quest 12개는 정확한 compatibility 규칙을 적용하고, 새로운/변경된 dialogue는 자동 통과시키지 않습니다.
- EFT profile-variable은 exact current 값이 있으면 정확히 판정합니다.
- 현재 EFT 1.1의 감사된 27-ID task-pool 구조가 완전히 일치하면 LL2~LL4는 현재 상인 LL과 완료 Quest로 복원합니다.
- LL1은 '완료 Quest 0개 + 현재 LL1' 초기 상태만 0으로 확정합니다. 그 밖의 LL1 진행 상태는 exact 값 없이 임의 추측하지 않습니다.
- 실제 완료 시각이 필요한 availability delay는 완료 시각을 모르면 계속 '확인 필요'입니다.
- current live 구조의 ID / 상인 / Quest 수 / threshold / seed 수가 감사 결과와 달라지면 해당 compatibility는 자동 중단되고 '확인 필요'로 fail-closed 합니다.

필요 아이템 / 보유량
- 미래에 진행할 수 있는 Quest와 은신처 업그레이드를 기준으로 필요한 아이템을 계산합니다.
- Quest 화면의 task-pool 호환 판정과 별개로 Needed Items는 불확실한 미래 Quest도 계속 잠재 필요 아이템으로 보호합니다.
- 따라서 '확인 필요'를 줄이기 위해 실제 필요한 아이템을 잘못 '정리 가능'으로 판단하도록 완화하지 않습니다.
- 유동 제출처럼 여러 후보 중 하나를 제출하는 요구사항도 후보 아이템을 보호합니다.

성능
- 아이템 수량 변경 시 Quest future reachability와 은신처 미래 요구조건 전체를 매번 다시 만들지 않고 inventory-dependent 계산만 갱신합니다.
- 아이템 수량 변경 때 전체 아이콘 로딩 파이프라인을 취소/재시작하지 않고 이미 로드한 아이콘을 재사용합니다.

지도 / MiniMap
- 지도 단축키, 마커, MiniMap 투명도/마커 크기 등 제품 설정은 %LocalAppData%\JunhyunHelper\map-product-settings.json에 저장됩니다.
- '퀘스트 마커 표시'도 같은 저장값을 사용하며 legacy 초기화가 이를 덮어쓰지 못하도록 했습니다.
- Main Map은 층 변경 시 live zoom + 보고 있던 중심을 보존합니다.
- MiniMap은 같은 지도의 층 변경 시 live 확대율과 X/Y 화면 위치를 그대로 보존합니다.
- Main Map 선택과 MiniMap이 공유하는 map key를 동기화해 오래된 다른 지도 상태가 남지 않도록 방어합니다.
- MiniMap hover 투명화는 별도 lightweight 주기로 감지해 빠르게 반응합니다.

게임 데이터 업데이트 / 호환성
- 온라인 데이터를 다운로드 → 검증 → canonical 변환 → candidate DB 생성 → 관계/read-back 검증 후에만 active 데이터로 교체합니다.
- 실패 candidate가 마지막 정상 Game Content를 덮어쓰지 않습니다.
- 데이터 업데이트는 user.db를 삭제하거나 덮어쓰지 않습니다.
- Runtime GPT/AI 의존성은 없습니다.
- Content schema: v7
- Readable Content schemas: v3, v4, v5, v6, v7
- user.db SQLite schema: v1
- v0.1.10 → v0.1.11 필수 데이터 업데이트: 없음
- 다음 정상 데이터 업데이트가 성공하면 v7 snapshot으로 저장합니다.
