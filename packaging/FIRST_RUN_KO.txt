준현 헬퍼 v1.3.5 — Windows x64

실행 방법
1. 받은 ZIP 파일을 원하는 폴더에 압축 해제합니다.
2. '준현 헬퍼.exe'를 실행합니다.
3. 처음 실행하면 프로필을 만들고 필요한 최신 게임 데이터를 온라인에서 내려받습니다.
4. 프로그램 실행 시 GitHub의 최신 정식 준현 헬퍼 릴리즈를 확인합니다. 더 최신 버전이 있으면 업데이트 여부를 묻습니다.

v1.3.5 주요 변경 — Scanner 상세창 추적 회귀 수정
- v1.3.4에서 strict HEADER_FRAME_LOCKED에 실패한 구조 후보를 detector 단계에서 완전히 제거하면서, 실제 상세창 구조를 찾고도 추적·로그·진단 이미지가 끊기는 회귀를 수정했습니다.
- 상세창 구조 후보는 제목 헤더 잠금에 실패해도 diagnostic-only 후보로 남아 구조 점수, anchor 점수와 실패 이유, 확인 가능한 부분 좌표를 로그와 인식 이미지에서 볼 수 있습니다.
- diagnostic-only 후보의 TitleImage는 null로 유지하므로 OCR이나 Item ID 확정에는 절대 사용되지 않습니다.
- fully locked 후보가 diagnostic-only 후보보다 항상 우선하며, OCR identity gate는 detector와 runtime 모두 HEADER_FRAME_LOCKED + anchor score 0.68 이상으로 통일했습니다.
- continuous Scanner는 header lock 실패 후보를 anchor-rejected 로그로 기록합니다.
- 1회 스캔에서 구조 후보 자체가 0개인 경우에도 one-shot-no-structural-candidate 로그를 남깁니다.
- 기존 OCR confidence, top1/top2 margin, 현재 공식 한국어 아이템 카탈로그 권위, 가격/필요 개수 의미와 모든 schema는 변경하지 않았습니다.

Scanner 사용
- '스캐너'는 EscapeFromTarkov 게임 창의 Borderless client-area를 실시간 감지합니다.
- '테스트'는 연결된 전체 디스플레이에 같은 인식 파이프라인을 적용합니다. 실사용 Scanner와 동시에 켤 수 없습니다.
- 1회 인게임 스캔 기본 단축키는 Ctrl+Shift+F10입니다.
- 1회 테스트 스캔 기본 단축키는 Ctrl+Shift+F11입니다.
- Scanner ON/OFF 기본 단축키는 Ctrl+Shift+F12입니다.
- 세 전역 단축키는 Scanner 탭을 보고 있지 않아도 준현 헬퍼가 실행 중이면 사용할 수 있습니다.
- '아이템 목록 최신화'는 현재 GameMode의 공식 한국어 전체 아이템 카탈로그를 갱신합니다.
- '인식 이미지'는 최신 캡처와 상세창/제목 ROI, 돋보기, 닫기 X, OCR 및 최종 판단을 확인하는 진단 기능입니다.
- '이미지 저장'을 선택하면 실제 캡처 픽셀 위에 초록=상세창, 파랑=제목 ROI, 노랑=돋보기, 빨강=닫기 X 진단 박스를 합성한 PNG를 저장합니다.
- '로그 삭제'는 최근 인식 기록, %LocalAppData%\JunhyunHelper\logs\scanner.log(.1), 최신 메모리 인식 이미지를 정리합니다. 사용자가 별도로 저장한 PNG는 삭제하지 않습니다.

Scanner 표시 데이터
- 최고 상점가: fleaMarket을 제외한 유효 판매처의 RUB 환산 가격 중 최댓값
- 플리마켓 평균가: positive avg24hPrice
- 상인/플리 가격·슬롯: 유효한 width × height 슬롯 수 기준
- 필요한 개수: 현재 Needed Items 계획의 RequiredTotal. 보유 Inventory를 뺀 부족량이 아닙니다.
- 가격이나 크기 정보가 누락되면 해당 표시 필드만 비우고 Item ID 식별 자체를 버리지 않습니다.

Scanner 인식 원칙
- 현재 공식 한국어 전체 아이템 카탈로그가 Item identity의 권위입니다.
- 상세창 구조 후보와 Item identity 후보는 분리합니다. 구조 후보는 진단을 위해 남을 수 있지만 HEADER_FRAME_LOCKED + anchor score 0.68을 충족하기 전에는 OCR을 실행하지 않습니다.
- 돋보기와 닫기 X는 위치 geometry뿐 아니라 icon-shape template evidence를 함께 사용합니다.
- Windows ko-KR OCR이 primary text recognizer입니다.
- OCR 텍스트는 current official catalog에서 실제 사용되는 문자/기호 정책으로 정리한 뒤 matcher에 전달합니다.
- confidence와 1·2순위 차이가 부족하면 Item ID를 확정하지 않습니다.
- 실제 스캔 순간에는 외부 API를 호출하지 않고, 아이콘도 새로 다운로드하지 않습니다.
- 게임 메모리 읽기, DLL injection, 패킷 가로채기를 사용하지 않습니다.

문제 피드백
- 인식이 실패하거나 잘못된 아이템으로 판단되면 다음 스캔 전에 '인식 이미지'에서 PNG를 저장하는 것이 가장 중요합니다.
- scanner.log에는 구조 후보, header anchor 실패 이유, OCR/matcher 판단이 기록됩니다.
- v1.3.5부터 구조는 찾았지만 header lock에 실패한 경우도 진단 evidence가 남습니다.

사용자 데이터
- 사용자 데이터는 프로그램 폴더가 아니라 %LocalAppData%\JunhyunHelper 에 저장됩니다.
- 프로그램 업데이트는 user.db, Game Content cache, 이미지 cache, Map/Ammo/Scanner 사용자 설정과 Scanner 로그를 교체하지 않습니다.
