준현 헬퍼 v0.1.13 — Windows x64

실행 방법
1. 받은 ZIP 파일을 원하는 폴더에 압축 해제합니다.
2. '준현 헬퍼.exe'를 실행합니다.
3. 처음 실행하면 프로필을 만들고 필요한 최신 게임 데이터를 온라인에서 내려받습니다.

배포 형태
- 설치 프로그램이 필요 없는 portable/self-contained Windows x64 빌드입니다.
- .NET/WPF/SQLite/Skia 런타임은 '준현 헬퍼.exe'에 포함됩니다.
- 지도 시스템이 경로로 직접 읽는 검증된 파일만 Assets 폴더에 둡니다.
- 실행 폴더 루트에는 '준현 헬퍼.exe', 이 안내문, Assets 폴더만 두는 것을 기준으로 합니다.
- 별도 .NET 설치나 관리자 권한은 필요하지 않습니다.
- 코드 서명이 되어 있지 않아 Windows SmartScreen 경고가 표시될 수 있습니다.

사용자 데이터
- 사용자 진행 데이터: %LocalAppData%\JunhyunHelper\user.db
- 게임 데이터: %LocalAppData%\JunhyunHelper\content
- 이미지 캐시: %LocalAppData%\JunhyunHelper\image-cache
- 지도 제품 설정: %LocalAppData%\JunhyunHelper\map-product-settings.json
- 지도 제품 설정 복구본: %LocalAppData%\JunhyunHelper\map-product-settings.json.bak
- 탄약 즐겨찾기: %LocalAppData%\JunhyunHelper\ammo-favorites.json
- 탄약 즐겨찾기 복구본: %LocalAppData%\JunhyunHelper\ammo-favorites.json.bak
- 프로그램 로그: %LocalAppData%\JunhyunHelper\logs\startup.log
- v0.1.12에서 v0.1.13으로 교체해도 기존 Profile / Quest / Inventory / Hideout / Map 설정은 유지됩니다.

v0.1.13 주요 변경 — 기존 기능 안정화
- 새로운 제품 기능은 추가하지 않았습니다.
- 지도 제품 설정과 탄약 즐겨찾기를 같은 폴더의 임시 파일에서 원자적으로 교체하고, 직전 정상본을 .bak 복구본으로 유지합니다.
- 설정 JSON이 손상된 경우 정상 복구본을 사용할 수 있으며, 손상된 primary가 다음 저장 때 정상 backup을 덮어쓰지 않도록 보호합니다.
- 지도/탄약의 부가 설정 저장 실패가 프로그램 전체 종료로 확대되지 않고 진단 로그로 남도록 처리했습니다.
- 지도 크기/마커 크기 등 슬라이더를 드래그하는 동안 매 변화마다 파일을 다시 쓰지 않고 짧게 묶어서 저장하며, 종료 전에 남은 값을 반영합니다.
- 지도 단축키와 NumPad 0~5 직접 층 선택의 비동기 실패를 앱 전체 오류로 확대하지 않고 진단 로그로 격리합니다.
- 키보드 hook 설치가 실패하면 원인을 진단 로그에 남깁니다.
- 게임 데이터 최종 검증에서 제출 아이템 후보가 비어 있거나 Quest/Hideout 필요 수량이 0 이하인 비정상 데이터를 active DB 적용 전에 차단합니다.
- 스캐너 탭은 기존대로 '준비 중' placeholder를 유지하며 실제 Scanner 기능은 추가하지 않았습니다.

검증 방식
- Release 빌드와 전체 자동 테스트를 통과해야 합니다.
- Windows x64 self-contained single-file publish 결과를 검사합니다.
- 실제 publish된 EXE를 실행해 기존 WPF 렌더 UI 계약을 검증합니다.
- Main Map / Factory / MiniMap / 정상 종료 smoke를 함께 실행합니다.
- 배포 루트에 불필요한 DLL/PDB/legacy dependency가 포함되지 않았는지 검사합니다.

퀘스트 판정 기준
- 서로 다른 taskRequirements는 AND, 한 requirement의 status[]는 OR입니다.
- 별도 '수주 가능' 상태를 만들지 않으며 게임에서 받을 수 있는 Quest는 Helper에서 즉시 수락한 것으로 간주합니다.
- source가 직접 제공한 prerequisite 의미를 우선하며 BTR Driver / Ref / Lightkeeper 특수 규칙도 기존 검증 정책을 유지합니다.
- 검증되지 않은 상태를 임의로 해금하지 않고 '확인 필요'로 유지합니다.
- EFT profile-variable exact current 값이 있으면 그 값을 권위값으로 사용합니다.
- 실제 완료 시각이 필요한 availability delay는 완료 시각을 모르면 '확인 필요'입니다.

필요 아이템 / 보유량
- 미래에 진행할 수 있는 Quest와 은신처 업그레이드를 기준으로 필요한 아이템을 계산합니다.
- 불확실한 미래 Quest도 Needed Items에서 잠재 필요 아이템으로 계속 보호합니다.
- 유동 제출처럼 여러 후보 중 하나를 제출하는 요구사항도 후보 아이템을 보수적으로 보호합니다.

게임 데이터 업데이트 / 호환성
- 온라인 데이터를 다운로드 → 검증 → canonical 변환 → candidate DB 생성 → 관계/read-back 검증 후에만 active 데이터로 교체합니다.
- 실패 candidate가 마지막 정상 Game Content를 덮어쓰지 않습니다.
- 데이터 업데이트는 user.db를 삭제하거나 덮어쓰지 않습니다.
- Runtime GPT/AI 의존성은 없습니다.
- Content schema: v7
- Readable Content schemas: v3, v4, v5, v6, v7
- user.db SQLite schema: v1
- v0.1.12 → v0.1.13 필수 데이터 업데이트: 없음

현재 범위
- 스캐너 탭은 현재 '준비 중' placeholder입니다.
- 지도 artwork/config/일반 marker bundle은 Quest/Hideout/Item/Ammo 온라인 데이터 업데이트와 별도로 관리합니다.
- EFT 1.0 Story Chapters는 현재 ordinary task source 범위 밖이며, 지원 범위 밖의 진행 조건을 임의로 추측하지 않습니다.
