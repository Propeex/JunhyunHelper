준현 헬퍼 v1.7.5 — Windows x64

실행 방법
1. 받은 'Junhyun-Helper.zip'을 원하는 위치에 압축 해제합니다.
2. 압축을 풀면 생성되는 '준현 헬퍼' 폴더 안의 '준현 헬퍼.exe'를 실행합니다.
3. 처음 실행하면 프로필을 만들고 필요한 최신 게임 데이터를 온라인에서 내려받습니다.
4. 프로그램 실행 시 GitHub의 최신 정식 준현 헬퍼 릴리즈를 확인합니다. 더 최신 버전이 있으면 업데이트 여부를 묻습니다.

v1.7.5 주요 변경 — Scanner OCR 환경 호환성 보호
- 일부 Windows PC에서 아이템 이름 OCR이 빈 결과를 매우 늦게 반환할 때 같은 OS OCR 호출이 여러 후보/복구 단계에서 연속 반복되어 Scanner가 장시간 멈춘 것처럼 보일 수 있던 구조를 보호합니다.
- OS OCR 호출이 800 ms 이상 걸린 뒤에도 읽은 텍스트가 비어 있을 때만 해당 OCR backend를 30초간 degraded 상태로 두고 추가 OS OCR 호출을 즉시 생략합니다.
- 느리더라도 유효한 텍스트를 반환한 OCR은 차단하지 않습니다. 정상 환경의 기존 OCR 성공 경로와 정확도 판정은 그대로 유지합니다.
- degraded 상태에서는 기존의 보수적인 Tarkov-font visual recovery가 현재 화면 픽셀과 현재 아이템 catalog를 사용해 식별을 계속 시도합니다. 충분한 근거가 없으면 기존과 같이 fail closed 합니다.
- scanner.log에 실제 OS OCR 호출 시간과 degraded/suppressed 상태를 기록하여 PC별 OCR backend 성능을 직접 확인할 수 있게 했습니다.
- v1.7.4의 non-backlogging 200 ms 관측 pacing과 v1.7.3의 adaptive semantic retry/direct BGRA OCR은 유지합니다.

Scanner 인식 안전 계약
- structural floor 0.34, HEADER_FRAME_LOCKED 0.68, continuous candidate cap 8, one-shot candidate cap 12는 그대로 유지합니다.
- false positive보다 miss를 선호하며, 이전 Item ID나 OCR 결과를 새 Item identity 증거로 사용하지 않습니다.
- cross-frame OCR 결과를 재사용하지 않습니다. 매 인식 판단의 제목 픽셀은 현재 화면에서 새로 획득합니다.
- OCR backend가 degraded되어도 matcher/visual recovery acceptance 기준을 완화하지 않습니다.
- Item ID가 확정되기 전에는 가격·필요 개수 같은 mapped data를 identity 증거로 사용하지 않습니다.
- Scanner 인식 중 네트워크 요청, 게임 메모리 읽기, DLL injection, packet interception을 사용하지 않습니다.

사용자 데이터
- 프로필, 진행도, Scanner 설정, 교정 데이터, 로그 등 변경 가능한 사용자 데이터는 프로그램 폴더가 아니라 %LocalAppData%\JunhyunHelper 아래에 보관됩니다.
- 프로그램 업데이트로 기존 사용자 진행도와 Scanner Ground Truth를 덮어쓰지 않습니다.
