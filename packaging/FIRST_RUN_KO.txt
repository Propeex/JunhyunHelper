준현 헬퍼 v0.1.12 — Windows x64

실행 방법
1. 받은 ZIP 파일을 원하는 폴더에 압축 해제합니다.
2. '준현 헬퍼.exe'를 실행합니다.
3. 처음 실행하면 프로필을 만들고 필요한 최신 게임 데이터를 온라인에서 내려받습니다.

배포 형태
- 설치 프로그램이 필요 없는 portable/self-contained Windows x64 빌드입니다.
- .NET/WPF/SQLite/Skia 런타임은 '준현 헬퍼.exe'에 포함됩니다.
- 지도 시스템이 경로로 직접 읽는 검증된 파일만 Assets 폴더에 둡니다.
- 실행 폴더 루트에는 '준현 헬퍼.exe', 이 안내문, Assets 폴더만 두는 것을 기준으로 합니다.
- 별도 .NET 설치나 관리자 권한은 필요하지 않습니다.
- 코드 서명이 되어 있지 않아 Windows SmartScreen 경고가 표시될 수 있습니다.

사용자 데이터
- 사용자 진행 데이터: %LocalAppData%\JunhyunHelper\user.db
- 게임 데이터: %LocalAppData%\JunhyunHelper\content
- 이미지 캐시: %LocalAppData%\JunhyunHelper\image-cache
- 지도 제품 설정: %LocalAppData%\JunhyunHelper\map-product-settings.json
- 탄약 즐겨찾기: %LocalAppData%\JunhyunHelper\ammo-favorites.json
- 프로그램 로그: %LocalAppData%\JunhyunHelper\Logs
- v0.1.11에서 v0.1.12로 교체해도 기존 Profile / Quest / Inventory / Hideout / Map 설정은 유지됩니다.

v0.1.12 주요 변경
- 유동 제출 아이템 행이 실제 렌더링에서도 전체 폭을 사용하도록 전용 Button template을 적용했습니다.
- 유동 제출 행은 아이콘 / 이름·분류 / 인레이드 / 일반의 고정 축을 유지하며, 인레이드·일반 수량은 오른쪽 기준으로 정렬됩니다.
- 탄약 즐겨찾기 버튼은 데이터 갱신 이후에도 '☆' 또는 '★'만 표시하도록 상태 갱신 코드까지 수정했습니다.
- 탄약 상세정보 손잡이는 42px 화살표 전용 버튼으로 바꾸고, 펼쳐짐은 ▼ / 접힘은 ▲로 표시합니다.
- 지도 진행 중 Quest 이름을 Button content에서 분리해 전역 Button 가운데 정렬 스타일의 영향을 제거했습니다.
- 지도 Quest 목록은 체크박스 30px / A·B·C·D marker 34px / Quest text 가변 열을 유지하므로 marker 유무와 관계없이 Quest 이름 시작 X축이 같습니다.
- 지도 Quest 패널 손잡이는 펼친 상태에서 패널의 오른쪽 바깥 경계, 즉 지도와 패널 사이에 붙도록 구조를 수정했습니다.

v0.1.12 검증 방식
- 단순 소스 문자열이나 빌드 성공만으로 UI 완료 처리하지 않습니다.
- 실제 WPF Measure/Arrange 결과를 배포 EXE 실행 중 검사합니다.
- 유동 제출 row가 전체 폭으로 확장되는지, icon/name/FIR/general lane이 의도한 축에 배치되는지 확인합니다.
- 탄약 즐겨찾기가 단일 ☆/★인지, 상세 손잡이가 expanded=▼ / collapsed=▲인지 확인합니다.
- 조건이 다른 지도 Quest 행들의 제목 시작 X좌표 편차가 0.75px 이하인지 확인합니다.
- 펼쳐진 지도 Quest 패널 손잡이가 오른쪽 경계에 붙는지 확인합니다.
- 기존 Main Map / Factory / MiniMap / 정상 종료 smoke도 함께 실행합니다.

퀘스트 판정 기준
- 서로 다른 taskRequirements는 AND, 한 requirement의 status[]는 OR입니다.
- 별도 '수주 가능' 상태를 만들지 않으며 게임에서 받을 수 있는 Quest는 Helper에서 즉시 수락한 것으로 간주합니다.
- source가 직접 제공한 prerequisite 의미를 우선하며 BTR Driver / Ref / Lightkeeper 특수 규칙도 기존 검증 정책을 유지합니다.
- 2026-08-17 live 데이터의 검증된 dialogue Quest 12개는 정확한 compatibility 규칙을 적용하고, 새로운/변경된 dialogue는 자동 통과시키지 않습니다.
- EFT profile-variable exact current 값이 있으면 그 값을 권위값으로 사용합니다.
- 현재 EFT 1.1 감사 구조가 완전히 일치할 때만 task-pool compatibility를 적용하며, 증명되지 않는 상태는 '확인 필요'로 유지합니다.
- 실제 완료 시각이 필요한 availability delay는 완료 시각을 모르면 '확인 필요'입니다.

필요 아이템 / 보유량
- 미래에 진행할 수 있는 Quest와 은신처 업그레이드를 기준으로 필요한 아이템을 계산합니다.
- 불확실한 미래 Quest도 Needed Items에서 잠재 필요 아이템으로 계속 보호합니다.
- 유동 제출처럼 여러 후보 중 하나를 제출하는 요구사항도 후보 아이템을 보호합니다.

게임 데이터 업데이트 / 호환성
- 온라인 데이터를 다운로드 → 검증 → canonical 변환 → candidate DB 생성 → 관계/read-back 검증 후에만 active 데이터로 교체합니다.
- 실패 candidate가 마지막 정상 Game Content를 덮어쓰지 않습니다.
- 데이터 업데이트는 user.db를 삭제하거나 덮어쓰지 않습니다.
- Runtime GPT/AI 의존성은 없습니다.
- Content schema: v7
- Readable Content schemas: v3, v4, v5, v6, v7
- user.db SQLite schema: v1
- v0.1.11 → v0.1.12 필수 데이터 업데이트: 없음

현재 범위
- 스캐너 탭은 현재 '준비 중' placeholder입니다.
- 지도 artwork/config/일반 marker bundle은 Quest/Hideout/Item/Ammo 온라인 데이터 업데이트와 별도로 관리합니다.
