# QUEST EXPERIENCE — 퀘스트 기능 제품 동작

상태: `CONFIRMED / 상세 UI 구현 전`

이 문서는 준현 헬퍼의 퀘스트 기능에서 사용자가 무엇을 보고 무엇을 조작하는지 정의합니다. 화면 배치 자체보다 **행동과 정보 구조**를 우선합니다.

## 1. 진행 동기화 원칙

퀘스트 진행은 게임 로그 자동 분석에 의존하지 않습니다.

- 준현 헬퍼가 게임 로그를 보고 퀘스트 완료를 자동 판정하지 않습니다.
- 사용자가 실제 게임에서 퀘스트를 완료한 뒤 준현 헬퍼에서 직접 `완료` 처리합니다.
- 이 수동 완료가 퀘스트 진행 상태의 유일한 사용자 입력입니다.
- 수주 가능한 퀘스트는 기존 결정대로 이미 수락한 것으로 간주합니다.

이 결정은 자동화보다 **신뢰도와 예측 가능성**을 우선합니다.

## 2. 정상 퀘스트 상태

사용자가 일반적으로 탐색하는 상태는 세 가지입니다.

- `진행 중` — 내부 `Current`. 해금 조건을 만족하고 아직 완료하지 않은 퀘스트.
- `잠김` — 내부 `Locked`. 현재 프로필의 확정된 조건으로 아직 해금되지 않은 퀘스트.
- `완료` — 내부 `Completed`. 사용자가 완료 처리한 퀘스트.

실제 게임의 `수주 가능`은 별도 상태로 관리하지 않습니다.

## 3. 완료 / 완료 취소

### 완료

진행 중 퀘스트에서 사용자가 `완료`를 실행하면:

1. 해당 프로필의 `CompletedQuestIds`에 Quest ID를 기록합니다.
2. 퀘스트 판정을 다시 계산합니다.
3. 후속 퀘스트와 필요 아이템 결과는 새 프로필 사실에서 다시 파생됩니다.

다른 기능의 저장 상태를 직접 수정하지 않습니다.

### 완료 취소

사용자가 실수로 완료 처리했거나 게임 상태와 맞추기 위해 수정할 수 있도록 `완료 취소`를 허용합니다.

1. 해당 Quest ID를 완료 집합에서 제거합니다.
2. 전체 퀘스트 판정을 다시 계산합니다.
3. 그 결과 영향을 받는 후속 퀘스트가 다시 잠길 수 있습니다.
4. 필요 아이템 역시 새 계산 결과에 따라 복원될 수 있습니다.

완료 취소는 단순히 사용자 사실 하나를 되돌리는 동작이어야 하며, 별도의 역동기화 로직을 만들지 않습니다.

## 4. Indeterminate — 판정 문제

`Indeterminate`는 `진행 중 / 잠김 / 완료`와 동급의 정상 게임 상태로 취급하지 않습니다.

의미:

> 현재 준현 헬퍼가 가진 데이터와 명시적 규칙만으로 이 퀘스트의 해금 여부를 안전하게 판정할 수 없음.

따라서 일반 상태 필터에 섞어 사용자가 게임 상태처럼 받아들이게 하지 않습니다.

### 기본 처리 방향

- 일반 퀘스트 목록에서는 정상 상태 3종을 중심으로 탐색합니다.
- `Indeterminate`가 존재하면 화면에 별도의 **판정 문제** 알림/진단 진입점을 제공합니다.
- 판정 문제 보기에서는 해당 Quest와 구체적인 이유를 보여줍니다.

현재 이유 예:

- 필요한 프로필 값 미입력
- 지원하지 않는 `dialogue` 등 availability condition
- 실패 상태를 알아야 하는 선행 퀘스트
- 참조 데이터 문제
- dependency cycle

사용자가 고칠 수 있는 문제(예: 프로필 값 미입력)와 데이터/프로그램 규칙 업데이트가 필요한 문제는 원인 정보를 통해 구분할 수 있어야 합니다.

프로그램은 Indeterminate를 임의로 `잠김` 또는 `진행 중`으로 변환하지 않습니다.

## 5. 목록 탐색

퀘스트는 전체를 볼 수 있어야 하며 기본 탐색 도구는 간단한 드롭다운 중심으로 구성합니다.

확정된 분류/필터 축:

- **상태**: 진행 중 / 잠김 / 완료 / 전체
- **상인**: 전체 또는 특정 상인
- **지도**: 전체 또는 특정 지도

검색은 퀘스트 수가 많으므로 함께 제공하는 것이 적절합니다.

상태/상인/지도 선택은 서로 조합될 수 있습니다.

예:

`잠김 + Prapor + Customs`

화면에서 진영/에디션/프레스티지를 별도 필터로 다시 선택하지 않습니다. 이것들은 선택된 프로필의 사실이며 퀘스트 판정 입력입니다.

## 6. 퀘스트 상세 — 권장 정보 구조

퀘스트를 클리어하기 위해 실제로 필요한 정보와, 왜 현재 상태인지 이해하는 데 필요한 정보만 우선합니다.

### A. 기본 정보

- 퀘스트 이름
- 상인
- 지도
- 현재 상태
- Wiki 열기

### B. 목표

- 게임의 Quest objective 설명 목록
- Optional 여부 등 원천에서 명확히 표현되는 속성
- 퀘스트 진행률을 준현 헬퍼에서 별도로 수동 체크하는 기능은 현재 필수가 아님

준현 헬퍼의 핵심 진행 단위는 **퀘스트 완료 여부**입니다.

### C. 필요한 아이템

해당 퀘스트가 실제로 제출을 요구하는 일반 아이템을 보여줍니다.

- Item 이름/아이콘
- 요구 수량
- FIR 여부
- 대체 가능한 아이템 그룹이면 그 사실을 명확히 표시

`findItem`이나 `sellItem`을 제출 아이템으로 잘못 표시하지 않습니다.

### D. 해금 조건

- 요구 레벨
- 진영
- 프레스티지
- 상인 평판/로열티
- 선행 퀘스트
- 에디션 제한

가능하면 현재 프로필 값과 비교해 충족/미충족을 구분합니다.

### E. 선행 퀘스트

직접 선행 퀘스트를 보여주고 클릭하면 해당 퀘스트 상세로 이동할 수 있게 합니다.

OR 조건이 존재하면 `A 또는 B`라는 관계를 잃지 않습니다.

### F. 분기/상호 배타 정보

원천 데이터에서 명확히 확인되는 경우 다른 선택지 또는 실패에 영향을 받는 퀘스트를 경고 형태로 보여줄 수 있습니다.

단, 실패 상태를 사용자가 어떻게 기록할지는 별도 제품 결정 전까지 자동 처리하지 않습니다.

### G. 보상

보상은 게임 정보 조회에 유용하므로 상세 하단에 표시하는 방향을 권장합니다.

우선순위 예:

- 경험치
- 돈/아이템
- 상인 평판
- 판매품 unlock

원천에서 안정적으로 정규화된 범위만 표시합니다.

## 7. 상세 화면의 행동

상태에 따라 주 행동을 하나만 명확하게 둡니다.

- 진행 중 → `완료`
- 완료 → `완료 취소`
- 잠김 → 진행 변경 버튼 없음
- 판정 문제 → 일반 완료 버튼보다 문제 원인 확인을 우선

Wiki는 상태와 무관하게 열 수 있습니다.

## 8. 하지 않을 것

현재 퀘스트 기능에서는 다음을 기본 요구로 만들지 않습니다.

- 로그 기반 자동 완료
- 별도 `수락` 버튼
- 개별 objective 진행을 필수로 수동 체크
- 추천 퀘스트 AI/휴리스틱
- 퀘스트 상태를 진영 토글 등 화면 임시값으로 재계산
- `Indeterminate`를 정상 게임 상태처럼 숨김 처리
- 화면 코드에서 퀘스트 조건을 다시 판정

## 9. UI 구현 방향

구체적인 스타일과 픽셀 배치는 구현 단계에서 결정합니다.

현재 적합한 기본 구조는:

`검색/드롭다운 필터 → 퀘스트 목록 → 선택한 퀘스트 상세`

입니다.

기존 Tarkov-Helper의 UI는 제품 사양이 아니라 참고 자료이며, 검토 결과는 `docs/LEGACY_UI_REFERENCE.md`에 별도로 기록합니다.
