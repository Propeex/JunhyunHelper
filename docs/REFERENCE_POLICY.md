# REFERENCE_POLICY — 기존 구현 및 외부 자료 참고 규칙

이 문서는 기존 Tarkov-Helper, RatScanner 및 기타 외부 구현을 새 제품 개발에서 어떻게 취급할지 정의합니다.

## 1. 기본 원칙

기존 구현은 **증거가 아니라 참고 자료**입니다.

어떤 코드가 이미 존재하거나 과거에 잘 동작했다는 사실만으로 새 제품의 요구사항, 게임 정보, UX, 기술 선택을 확정하지 않습니다.

## 2. 기존 `Propeex/Tarkov-Helper`

허용되는 사용:

- 과거 해결하려 했던 사용자 문제 파악
- 기능 아이디어 후보 발굴
- 파일 형식/프로토콜/라이브러리 사용 사례 조사
- 반복해서 발생했던 버그나 제약 탐색
- 재사용 가능성이 있는 코드/자산 후보 탐색
- 새 설계와 비교하기 위한 참고

금지되는 사용:

- 기존 UI/동작을 자동으로 새 사양으로 채택
- 기존 코드에 있는 게임 수치/규칙을 검증 없이 사실로 사용
- 기존 아키텍처를 기본값으로 승계
- “예전에도 이렇게 했으니”만으로 기술 선택
- 기존 버그나 제한을 새 제품의 필수 제약으로 오인

## 3. RatScanner 등 타 프로젝트

다른 프로젝트도 동일하게 참고 구현으로 취급합니다.

타 프로젝트에서 좋은 아이디어를 발견해도 다음을 별도로 판단합니다.

- 우리 사용자의 실제 문제와 맞는가
- Tarkov 현재 환경에서 여전히 유효한가
- 라이선스/재사용 조건에 문제가 없는가
- 새 제품 구조에 적합한가
- 더 단순하거나 정확한 방법이 있는가

## 4. 참고 내용을 채택하는 절차

중요한 기존 아이디어/코드/동작을 새 제품에 반영하려면 다음 흐름을 따릅니다.

1. **관찰** — 기존 구현이 무엇을 하는지 확인
2. **의도 분리** — 왜 존재하는 기능인지 추정하고 필요하면 사용자에게 확인
3. **사실 검증** — 게임 정보/외부 조건이 현재도 맞는지 검증
4. **새 요구사항과 비교** — 현재 `PRODUCT.md`의 요구와 일치하는지 판단
5. **독립 설계** — 기존 구조에 얽매이지 않고 가장 적합한 새 설계를 선택
6. **결정 기록** — 장기적인 영향이 있으면 `DECISIONS.md`에 이유와 함께 기록

## 5. 정보 출처의 신뢰도

제품에 영향을 주는 게임 정보는 출처의 성격을 구분합니다.

예시 범주:

- 게임/개발사의 공식 정보
- 현재 상태를 직접 제공하는 신뢰 가능한 데이터 소스/API
- 검증 가능한 커뮤니티 데이터베이스
- 제3자 구현의 하드코딩 값
- 오래된 문서/게시물/추정

구체적인 데이터 공급원과 우선순위는 제품 요구사항을 파악한 뒤 별도로 확정합니다.

## 6. 불일치가 발견된 경우

기존 Tarkov-Helper와 새로 검증한 정보가 다르면 **기존 구현을 보존하려고 새 설계를 왜곡하지 않습니다.**

다음 순서로 처리합니다.

1. 현재 사실을 다시 확인
2. 사용자에게 영향을 주는 차이를 설명
3. 새 제품 요구에 맞는 동작을 결정
4. 필요하면 결정 기록
5. 구현/테스트/문서를 새 기준에 맞춤

## 7. 핵심 판단 문장

> “기존 Tarkov-Helper가 이렇게 한다”는 것은 조사 시작점일 수 있지만, 새 Tarkov Helper가 그렇게 해야 한다는 근거는 아니다.
