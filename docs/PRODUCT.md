# PRODUCT — 준현 헬퍼 제품 정의

이 문서는 **무엇을 만들고 왜 만드는지**를 정의하는 공식 제품 설계 문서입니다.

사용자가 구두로 전달한 아이디어는 곧바로 완성된 요구사항으로 간주하지 않습니다. 개발자가 이해한 내용을 사용자와 맞추고 실제 작동 방식까지 합의된 내용만 `CONFIRMED` 요구사항으로 기록합니다.

## 1. 제품 이름

`CONFIRMED`

**준현 헬퍼**

저장소 이름은 `JunhyunHelper`이지만 사용자에게 보이는 공식 제품명은 **준현 헬퍼**입니다.

## 2. 제품의 핵심 정의

`CONFIRMED`

준현 헬퍼는 Escape from Tarkov의 최신 게임 데이터를 온라인 데이터 공급원에서 받아 **프로그램 스스로 해석 가능한 내부 데이터베이스로 변환·재구축**하고, 그 데이터를 사용자의 게임 진행 상태와 결합해 플레이에 필요한 정보를 제공하는 데스크톱 헬퍼입니다.

핵심은 특정 패치의 퀘스트/은신처/탄약 내용을 프로그램에 수작업으로 박아 넣는 것이 아닙니다.

**게임 데이터의 내용이 바뀌어도 외부 데이터가 호환 가능한 형식을 유지하는 한, 준현 헬퍼가 최신 데이터를 다시 내려받아 같은 변환 규칙으로 내부 데이터베이스를 새로 만들 수 있어야 합니다.**

또한 Game Content 업데이트와 User Progress는 분리합니다. 사용자가 입력한 캐릭터 진행과 보유 아이템은 패치 데이터가 바뀌었다는 이유로 삭제하거나 덮어쓰지 않습니다.

## 3. 최상위 데이터 원칙

`CONFIRMED`

### GPT/개발자의 역할

GPT 또는 개발자는 개발 과정에서 다음을 담당합니다.

- 외부 API 데이터 구조 분석
- 준현 헬퍼가 필요한 정보의 의미 정의
- 외부 데이터 → 준현 헬퍼 내부 데이터 모델의 변환 규칙 설계 및 구현
- 형식 검증과 오류 처리 규칙 구현

### 프로그램의 역할

프로그램이 만들어진 뒤 일반적인 게임 데이터 업데이트에는 GPT의 재해석이 필요하지 않아야 합니다.

기본 갱신 흐름은 다음과 같습니다.

`온라인 API → 원본 데이터 다운로드 → 형식 검증 → 내부 모델로 변환 → 로컬 데이터베이스 재구축/갱신 → 기능에서 사용`

즉, **GPT가 매 패치마다 새 데이터를 읽고 변환해 주는 구조를 만들지 않습니다.**

### 외부 API 형식에 대한 안전 원칙

외부 API의 데이터 형식이 영원히 바뀌지 않는다고 보장할 수는 없습니다.

- 값, 퀘스트 내용, 필요 수량 등 **내용 변화**는 프로그램이 자동으로 흡수해야 합니다.
- 기존 변환기가 이해할 수 있는 **호환 가능한 필드 추가/변화**도 가능한 한 안전하게 처리합니다.
- 핵심 필드 삭제/의미 변경 등 **비호환 스키마 변경**이 발생하면 잘못된 데이터베이스를 만드는 대신 이를 감지하고 안전하게 갱신을 중단해야 합니다.
- 비호환 변경이 실제로 발생한 경우 변환 코드 자체의 업데이트는 필요할 수 있지만, 일반적인 패치 데이터 변경 때마다 GPT나 사람이 데이터를 다시 작성하는 구조는 허용하지 않습니다.

## 4. 현재 핵심 기능 범위

### CORE-001 — API 기반 데이터베이스 업데이트

`CONFIRMED`

온라인 데이터 공급원에서 최신 데이터를 받아 준현 헬퍼 내부 데이터베이스로 변환·갱신합니다.

현재 API 기반 핵심 데이터:

- 퀘스트
- 은신처
- 탄약
- 위 기능과 관계 계산에 필요한 아이템/상인/맵/교환/제작 데이터

현재 1차 원천은 `json.tarkov.dev`이며, 에디션별 퀘스트 규칙은 별도의 검증된 editions-only 보조 원천을 사용합니다.

지도는 아직 적절한 API 공급원을 확정하지 않았으므로 이 데이터 파이프라인의 현재 확정 범위에서 제외합니다.

### CORE-002 — 퀘스트

`CONFIRMED`

- 선택된 게임 진행 프로필을 기준으로 현재 퀘스트를 계산합니다.
- 실제 게임에서 수주 가능한 퀘스트는 준현 헬퍼에서 이미 수락된 것으로 간주합니다.
- 사용자가 게임에서 퀘스트를 완료하면 준현 헬퍼에서도 수동 완료 처리하고 후속 퀘스트 판정을 갱신합니다.
- 완료 취소를 지원합니다.
- 진행 중 / 잠김 / 완료 상태를 탐색할 수 있습니다.
- 장소(맵) 또는 상인 기준으로 분류할 수 있어야 합니다.
- 퀘스트 설명/목표 등 클리어에 필요한 정보와 Wiki 페이지를 확인할 수 있어야 합니다.
- 안전하게 판정할 수 없는 조건은 정상 상태에 섞지 않고 `Indeterminate` 진단으로 다룹니다.

### CORE-003 — 은신처

`CONFIRMED`

- 최신 은신처 데이터를 내부 데이터베이스로 변환하여 사용합니다.
- 사용자가 시설별 현재 레벨을 직접 입력합니다.
- `미입력`과 `Lv.0`은 서로 다른 상태입니다.
- 은신처 화면은 현재 레벨에서 바로 다음 업그레이드 정보를 표시합니다.
- 필요 아이템 계산에서는 **명시된 현재 레벨 이후의 모든 미래 업그레이드 요구 아이템**을 보관 계획에 포함합니다.
- 현재 레벨이 미입력인 시설은 프로그램이 Lv.0이라고 추측하지 않으며, 해당 시설과 관련된 보유 아이템을 함부로 `정리 가능`으로 판정하지 않습니다.

### CORE-004 — 탄약

`CONFIRMED`

탄약은 선택된 게임 모드의 최신 Game Content를 **읽기 전용으로 비교·조회하는 기능**입니다.

- 구경 dropdown과 이름 검색으로 탄약을 찾습니다.
- 표에서 피해량, 발사체 수, 관통력, 장갑 피해, 초속, 파편 확률, 명중/반동 보정 등 canonical 탄약 사실을 비교합니다.
- 산탄처럼 발사체가 여러 개인 경우 프로그램이 피해량을 임의 합산하거나 별도 효율 점수를 만들지 않고 `개별 피해 × 발사체 수`를 그대로 표시합니다.
- 선택한 탄약의 수급처를 상인 직접 구매, 물물교환, 은신처 제작으로 구분해 보여줍니다.
- 수급처에서 확인 가능한 상인/시설 레벨, 가격, 교환·제작 재료, 구매 제한, 제작 시간, 결과 수량, 퀘스트 해금 조건을 표시합니다.
- 기존 Tarkov-Helper의 자체 `방어구 효율` 같은 휴리스틱 점수를 게임 사실처럼 승계하지 않습니다.
- 탄약 기능은 별도의 사용자 진행 상태를 저장하지 않으며 Quest/Hideout/Needed Items 계산 흐름에 결합하지 않습니다.
- Game Content가 갱신되면 새 canonical 탄약과 수급 관계를 다시 표시합니다.

### CORE-005 — 필요 아이템

`CONFIRMED`

필요 아이템은 별도로 수작업 관리하는 고정 데이터베이스가 아니라 **최신 퀘스트 데이터, 최신 은신처 데이터, 현재 사용자 진행 상태에서 매번 계산하는 파생 정보**입니다.

이 기능의 목적은 지금 당장 필요한 물건만 보여주는 것이 아니라, **현재 캐릭터가 앞으로 사용할 가능성이 있는 물건을 미리 모으고 더 이상 필요하지 않은 보유품은 제때 정리할 수 있게 하는 것**입니다.

기본 미래 필요 범위:

- 현재 진행 중인 퀘스트의 제출 아이템
- 레벨/상인/프레스티지/선행 진행 등 앞으로 충족할 수 있는 조건 때문에 잠겨 있는 미래 퀘스트의 제출 아이템
- 아직 닫히지 않은 가능한 분기의 요구 아이템
- 명시된 현재 은신처 레벨 이후 모든 미래 업그레이드 재료

제외:

- 완료된 퀘스트
- 현재 캐릭터의 진영/에디션/게임 모드 등으로 명시적으로 수행 불가능한 퀘스트
- 확정된 진행 때문에 영구적으로 닫힌 것으로 증명 가능한 경로

안전 원칙:

- 미래 가능성을 정확히 판단하지 못하는 조건은 정리 대상으로 추측하지 않고 보수적으로 보관 가능성에 남깁니다.
- 대체 제출 아이템 여러 개 중 하나를 프로그램이 임의로 선택하지 않습니다.
- 사용자 보유량은 User Progress의 독립 사실이며 Game Content 업데이트로 삭제하지 않습니다.
- `보유량 > 현재 미래 필요량`이면 초과분을 `정리 필요`로 표시합니다.
- `필요량 = 0`이 되어도 보유량이 남아 있으면 Item 화면에서 사라지지 않고 사용자가 실제 보유량을 수정할 때까지 정리 대상으로 남습니다.
- 업데이트나 진행 변화로 새 정리 가능 수량이 생기면 사용자가 인지할 수 있게 알립니다.
- FIR 요구량을 보존한 뒤 실제로 안전하게 정리 가능한 FIR/Non-FIR 수량만 계산합니다.
- 퀘스트 완료 시 보유량을 자동 차감하거나, 필요 없어졌다는 이유로 보유량을 자동 삭제하지 않습니다.

세부 기준은 `docs/NEEDED_ITEMS_EXPERIENCE.md`를 따릅니다.

## 5. 후속/별도 기능

### 지도

`INTENT_CAPTURED / DATA SOURCE OPEN`

지도에서 각종 정보를 확인하고 미니맵 형태로 인게임 중 사용하는 방향은 유지합니다. 다만 현재 적절한 지도 API를 확보하지 않았으므로 핵심 API 데이터베이스 파이프라인과 분리해 둡니다.

### RatScanner 기능 통합

`INTENT_CAPTURED / LATER`

RatScanner의 필요한 기능을 준현 헬퍼에 통합하는 방향은 유지하지만 현재 핵심 데이터 기능 이후의 후속 범위입니다.

## 6. 게임 진행 프로필

`CONFIRMED`

PvP, PvE, 시즌 계열 등 서로 다른 Tarkov 캐릭터는 서로 독립된 게임 진행 프로필로 관리합니다.

각 프로필에는 해당 캐릭터에 종속되는 실제 사용자 사실을 저장합니다.

- 레벨
- 진영(BEAR/USEC)
- 상인 평판/로열티
- 게임 에디션
- 프레스티지
- 완료 퀘스트
- 은신처 시설별 현재 레벨
- 아이템 보유량(FIR / Non-FIR)

현재 퀘스트 상태, 미래 필요량, 정리 가능량 같은 계산 결과는 프로필에 진실의 원천으로 저장하지 않습니다.

## 7. 퀘스트 핵심 사용 흐름

### FLOW-001 — 현재 가능한 퀘스트 확인 및 완료 동기화

- 상태: `CONFIRMED`
- 시작 상황: 사용자가 준현 헬퍼의 퀘스트 기능을 엽니다.
- 사용자 목표: 실제 게임의 현재 캐릭터 상태에서 수행 가능한 퀘스트와 준현 헬퍼의 목록을 최대한 일치시킵니다.
- 사용자의 입력/행동: 선택된 게임 진행 프로필의 캐릭터 정보를 관리하고, 게임에서 퀘스트를 완료하면 준현 헬퍼에서도 완료 처리합니다.
- 프로그램의 동작: 해당 게임 모드의 전체 퀘스트 데이터와 현재 프로필의 상태를 비교하여 선행 조건을 만족한 미완료 퀘스트를 계산합니다.
- 프로그램의 출력: 실제 게임에서 수주 가능한 퀘스트를 준현 헬퍼에서는 이미 수락된 `현재 퀘스트`로 보여줍니다.
- 완료 조건: 게임에서 퀘스트 완료 → 준현 헬퍼에서 완료 처리 → 후속 퀘스트 및 필요 아이템 재계산.

## 8. 퀘스트 확정 요구사항

### REQ-001 — 현재 퀘스트 자동 판정

- 상태: `CONFIRMED`
- 최신 퀘스트 데이터의 선행 조건과 선택된 게임 진행 프로필의 상태를 비교하여 조건을 만족하고 아직 완료되지 않은 퀘스트를 자동 계산해야 합니다.
- 실제 게임의 `잠김 → 수주 가능 → 진행 중` 중 준현 헬퍼는 수주 가능한 퀘스트를 모두 수락한다고 가정합니다.
- 준현 헬퍼 상태는 `잠김 → 현재 퀘스트 → 완료`로 단순화합니다.

### REQ-002 — 퀘스트 완료 동기화

- 상태: `CONFIRMED`
- 사용자가 퀘스트를 완료 처리하면 선택된 진행 프로필에 완료 상태를 저장하고 후속 퀘스트 해금 판정과 미래 필요 아이템을 다시 계산해야 합니다.
- 완료 취소도 같은 원리로 완료 사실만 되돌린 뒤 재계산합니다.

### REQ-003 — 시간 지연 해금 제외

- 상태: `CONFIRMED`
- `AvailableAfter`와 같은 실제 시간 지연 조건은 준현 헬퍼의 해금 판정에서 제외합니다.
- 준현 헬퍼가 실제 게임에서의 정확한 완료 시각을 알 수 없기 때문입니다.
- 시간 외 확인 가능한 조건을 만족하면 현재 퀘스트로 표시하며, 일부 퀘스트가 게임보다 일찍 표시될 수 있는 것은 의도된 차이입니다.

## 9. 퀘스트 해금 조건의 큰 범위

현재 확인된 조건 계열:

- 캐릭터 레벨
- 진영
- 선행 퀘스트 상태
- 상인 평판
- 상인 로열티 레벨
