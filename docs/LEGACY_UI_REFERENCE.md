# LEGACY UI REFERENCE — 기존 Tarkov-Helper UI 회수 검토

상태: `REFERENCE ONLY`

대상: `Propeex/Tarkov-Helper`

목적:

> 기존 프로그램의 제품 설계나 내부 구조를 계승하지 않고, 실제 사용성이 괜찮았던 **UI 패턴만** 준현 헬퍼 구현 참고자료로 남깁니다.

기준은 항상 준현 헬퍼의 제품 요구사항입니다.

## 1. 적극 참고할 패턴

### 상단 탭 내비게이션

기존 MainWindow는 퀘스트/은신처/아이템/탄약/지도 등을 상단 탭으로 전환합니다.

준현 헬퍼에서도 핵심 기능 수가 적으므로 복잡한 사이드바보다 이런 **고정된 주요 기능 탭**이 적절한 후보입니다.

참고할 것:

- 현재 기능이 명확하게 보임
- 클릭 한 번으로 주요 영역 이동
- 선택 상태가 분명함

참고하지 않을 것:

- MainWindow가 각 기능의 서비스와 진행 로직까지 직접 관리하는 구조

### 검색 + 드롭다운 필터 바

기존 QuestListPage는 상단에:

- 검색
- 상인 ComboBox
- 지도 ComboBox
- 상태 ComboBox

를 한 줄에 배치합니다.

준현 헬퍼의 새 퀘스트 요구사항과 매우 잘 맞습니다.

채택 방향:

- 상태 / 상인 / 지도는 드롭다운
- 검색 입력 제공
- 필터를 조합 가능하게 유지
- 데이터가 많아져도 필터 자체는 단순한 값 선택에 머무름

제외:

- 진영을 퀘스트 화면에서 다시 토글
- 에디션 등을 목록 필터로 중복 선택

이 값들은 Profile의 사실입니다.

### 목록 + 우측 상세 패널

기존 QuestListPage와 HideoutPage 모두:

`왼쪽 목록 | splitter | 오른쪽 상세`

구조를 사용합니다.

장점:

- 목록을 잃지 않고 여러 항목을 빠르게 비교/열람 가능
- 상세 창을 새로 띄울 필요가 없음
- 데스크톱의 가로 공간 활용에 적합
- splitter로 상세 폭 조절 가능

준현 헬퍼 Quest / Hideout에 우선 검토할 패턴입니다.

### 목록 행의 작은 주 행동 버튼

기존 Quest 목록은 진행 중 항목 행 우측에 `완료` 버튼을 둡니다.

준현 헬퍼에도 적합합니다.

권장:

- 진행 중 행 → `완료`
- 완료 행에서 빠른 취소까지 둘지는 실제 화면 밀도를 보고 결정
- 상세 패널에서는 상태에 따라 `완료` 또는 `완료 취소` 하나를 명확히 제공

버튼을 많이 늘리지 않습니다.

### 상태 Badge

기존 UI는 잠김/진행/완료 등을 작은 색상 Badge로 구분합니다.

상태를 빠르게 스캔하는 데 유용하므로 참고합니다.

준현 헬퍼에서는 정상 상태:

- 진행 중
- 잠김
- 완료

만 기본 badge 대상으로 합니다.

`Indeterminate`는 일반 상태 badge가 아니라 별도의 판정 문제 표시가 적절합니다.

### 퀘스트 상세의 정보 섹션 분할

기존 상세 패널은:

- 기본 정보
- 필요 아이템
- 요구 사항
- 목표
- 선행 퀘스트
- 분기 정보
- Wiki 행동

을 작은 섹션으로 구분합니다.

정보 구조 자체는 참고 가치가 큽니다.

준현 헬퍼에서는 데이터가 실제로 필요한 섹션만 렌더링하고 빈 섹션은 숨깁니다.

### 선행 퀘스트 클릭 이동

기존 UI는 상세의 선행 퀘스트명을 클릭해 그 퀘스트로 이동할 수 있습니다.

복잡한 기능 없이 탐색성이 크게 좋아지므로 채택 후보입니다.

### FIR badge + Item icon

기존 Quest/Hideout/Items 화면에서 FIR을 작은 badge로 보여주고 item icon을 함께 사용합니다.

필요 아이템 조건을 빠르게 이해하는 데 유용합니다.

### 은신처 +/- 레벨 조작

기존 Hideout 목록은 시설 현재 레벨 옆에 작은 `- / +` 버튼을 둡니다.

게임에서 시설 업그레이드 후 준현 헬퍼를 맞추는 용도로 매우 직접적이므로 새 Hideout UX에서도 참고할 가치가 높습니다.

### 탄약 구경 드롭다운 + 표

기존 AmmoPage의:

`구경 ComboBox → DataGrid`

구조는 탄약 조회 기능의 목적과 잘 맞습니다.

또한 많은 열 중 표시할 열을 Popup 체크박스로 선택하는 방식도 정보량이 많을 경우 참고할 수 있습니다.

다만 어떤 열을 제공할지는 준현 헬퍼의 실제 Ammo model과 제품 우선순위가 결정합니다.

## 2. 조건부 참고

### 프로필 드롭다운/Drawer

기존 MainWindow의 `프로필` 버튼에서 작은 설정 drawer를 여는 상호작용은 빠른 접근성 면에서 좋습니다.

준현 헬퍼에서는 Profile이 더 명확한 도메인이므로:

- 현재 프로필 선택은 상단의 간단한 selector
- 프로필 값 편집은 별도 작은 편집 화면/패널

정도로 분리하는 것이 더 단순할 수 있습니다.

기존처럼 여러 게임 값을 MainWindow title bar에 직접 늘어놓지는 않습니다.

### 탄약 표시 열 설정 Popup

사용자가 표를 커스터마이즈할 수 있어 유용하지만 첫 구현에 반드시 필요하지는 않습니다.

기본 열이 과도해질 때 도입합니다.

## 3. 가져오지 않을 UI/행동

### Quest 추천 패널

기존 `QuestRecommendationsPanel`은 준현 헬퍼 핵심 목표가 아닙니다.

규칙/휴리스틱이 추가되고 유지보수 면적만 넓힐 가능성이 있으므로 현재 제외합니다.

### 카파 전용 진행 Gauge/특수 화면

특정 Quest 하나를 위한 특수 UI는 핵심 흐름을 복잡하게 만듭니다.

일반적인 Quest 데이터로 표현 가능한 정보는 일반 상세 화면에서 처리합니다.

### Quest 화면의 BEAR/USEC 토글

진영은 Profile 사실입니다.

Quest 화면 필터 값으로 다시 설정하면 상태 원천이 중복됩니다.

### Objective 수동 체크

기존 UI는 Quest 내부 objective마다 checkbox 진행을 저장합니다.

사용자는 준현 헬퍼의 진행 동기화를 Quest 완료 단위로 하기로 결정했으므로 현재 기본 기능에서 제외합니다.

### `초기화`라는 모호한 Quest 버튼

기존 상세에는 Quest 상태를 Reset하는 `초기화` 버튼이 있습니다.

새 제품은 의도가 명확한 `완료` / `완료 취소`를 사용합니다.

### UI 코드에서 데이터 규칙 판정

기존 QuestListPage code-behind에는 상태 판정, Profile 반응, 데이터 로딩, 필터, 상세 렌더링, 추천, 카파 등이 한 클래스에 모여 있습니다.

시각적인 화면 구조는 참고하지만 이 구현 구조는 가져오지 않습니다.

준현 헬퍼 UI는 Core query 결과를 표시하고 명령만 전달해야 합니다.

## 4. 준현 헬퍼에 권장되는 Quest 화면 초안

```text
[퀘스트]

[검색........] [상태 ▼] [상인 ▼] [지도 ▼]       [판정 문제 2]

┌──────────────────────────────┬────────────────────────────┐
│ 퀘스트 목록                   │ 선택 퀘스트 상세             │
│                              │                            │
│ Prapor  Debut        진행 중 │ Debut                      │
│         [완료]               │ Prapor · Customs · 진행 중 │
│                              │ [Wiki]          [완료]     │
│ ...                          │                            │
│                              │ 목표                       │
│                              │ 필요 아이템                │
│                              │ 해금 조건                  │
│                              │ 선행 퀘스트                │
│                              │ 보상                       │
└──────────────────────────────┴────────────────────────────┘
```

이것은 최종 디자인이 아니라 **참고 UI 구조**입니다.

## 5. 결론

기존 Tarkov-Helper UI에서 가장 가치 있는 것은 특정 색상이나 XAML 코드가 아니라 다음 상호작용 패턴입니다.

1. 적은 수의 상위 탭
2. 검색 + ComboBox 필터
3. 목록/상세 split view
4. 상태 badge
5. 상황에 맞는 단일 주 행동 버튼
6. 섹션화된 상세 정보
7. 클릭 가능한 관계 탐색
8. Item icon/FIR 같은 작은 시각 신호
9. 숫자 진행값의 간단한 +/- 조작
10. 표형 정보에는 dropdown + DataGrid

준현 헬퍼에서는 이 사용성만 참고하고 기존 화면의 서비스 결합, 이벤트 체인, 특수 기능 누적 구조는 승계하지 않습니다.
