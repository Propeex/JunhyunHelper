# NEEDED ITEMS EXPERIENCE — 필요 아이템 제품 기준

상태: `CONFIRMED`

날짜: 2026-08-08

이 문서는 준현 헬퍼의 **필요 아이템 기능이 왜 존재하는지**, 어떤 아이템을 보관 대상으로 계산하는지, 게임 데이터/진행 상태가 바뀌어 더 이상 필요하지 않게 된 보유 아이템을 어떻게 다루는지를 정의합니다.

## 1. 존재 이유

준현 헬퍼의 필요 아이템 기능은 단순한 현재 퀘스트 체크리스트가 아닙니다.

사용자가 Tarkov를 플레이하면서 **미래의 퀘스트와 은신처 업그레이드에 언젠가 필요할 아이템을 미리 모아두고, 필요 없어진 물건은 제때 정리할 수 있게 하는 것**이 핵심 목적입니다.

이 기능은 특히 대형 게임 업데이트 후 퀘스트/은신처 요구 아이템이 변경되더라도, 사용자가 이전 요구사항을 믿고 모아둔 아이템을 이유도 모른 채 계속 보관하는 문제를 방지해야 합니다.

## 2. 보유량과 필요량은 서로 다른 사실이다

### 사용자 보유량

사용자가 직접 입력한 인벤토리 수량은 **User Progress의 독립적인 사용자 사실**입니다.

- 외부 Game Content 업데이트로 삭제하지 않습니다.
- 퀘스트가 완료되거나 분기가 닫혀도 자동으로 삭제하지 않습니다.
- 필요량이 0이 되어도 보유량은 그대로 남습니다.

### 필요량

필요량은 Game Content + 현재 사용자 진행 상태에서 매번 계산하는 **파생 정보**입니다.

따라서:

`보유량 != 필요량`

이며 둘을 같은 데이터로 관리하지 않습니다.

## 3. 기본 필요 아이템 범위

필요 아이템은 '지금 바로 필요한 것'만이 아니라 **현재 캐릭터가 앞으로 도달할 가능성이 남아 있는 모든 경로의 요구 아이템**을 포함합니다.

포함 대상:

- 현재 진행 중인 퀘스트의 제출 아이템
- 아직 잠겨 있지만 현재 캐릭터가 미래에 도달 가능한 퀘스트의 제출 아이템
- 아직 결정되지 않은 여러 가능한 퀘스트 분기가 있다면 각 분기에서 미래에 필요할 수 있는 아이템
- 현재 은신처 레벨 이후 미래 업그레이드에서 필요한 아이템

제외 대상:

- 이미 완료되어 더 이상 제출할 필요가 없는 퀘스트 요구량
- 진영/에디션/게임 모드/확정된 분기 등 명시적인 이유로 현재 캐릭터가 더 이상 수행할 수 없는 퀘스트
- 의미를 안전하게 판정할 수 없는 요구사항을 프로그램이 임의로 추측한 결과

즉, 단순한 `Current / Locked` 상태가 아니라 **미래 도달 가능성**을 필요 아이템 계산에 사용합니다.

## 4. 미래 가능성과 영구 불가능을 구분한다

잠긴 퀘스트라고 해서 필요 아이템에서 제외하지 않습니다.

예:

- 레벨 부족 → 미래 가능 → 포함
- 아직 선행 퀘스트 미완료 → 미래 가능 → 포함

반면 현재 캐릭터에서 수행할 수 없음이 명시적으로 확정되면 제외합니다.

예:

- 다른 퀘스트 분기를 선택해 해당 분기가 영구적으로 닫힘
- 현재 에디션에서 제외되는 퀘스트
- 현재 진영에서 수행할 수 없는 퀘스트
- 현재 게임 모드에서 존재하지 않는 퀘스트

프로그램은 모르는 조건을 '아마 가능' 또는 '아마 불가능'으로 추측하지 않습니다.

## 5. 요구량이 바뀌어도 보유량은 보존한다

Game Content 업데이트 또는 사용자 진행 변화로 필요량이 달라질 수 있습니다.

예:

- 퀘스트 제출 아이템 변경
- 제출 수량 변경
- 퀘스트 삭제/비활성화
- 에디션/진영/분기 때문에 퀘스트 경로가 닫힘
- 은신처 업그레이드 요구량 변경
- 사용자가 퀘스트를 완료함
- 사용자가 은신처 레벨을 올림

이때 준현 헬퍼는 **필요량만 다시 계산**합니다.

사용자가 입력한 보유 수량은 자동으로 삭제하거나 덮어쓰지 않습니다.

## 6. 초과 보유 아이템 — 정리 필요

어떤 아이템이든:

`사용자 보유량 > 현재 계산된 미래 필요량`

이면 차이는 **초과 보유량**입니다.

특히:

`필요량 = 0` 이고 `보유량 > 0`

이면 해당 아이템은 Game Content/현재 진행 경로에서는 더 이상 보관 이유가 없지만 사용자 데이터에는 남아 있는 상태입니다.

준현 헬퍼는 이를 조용히 목록에서 사라지게 하지 않습니다.

아이템 화면에 별도의 **정리 필요** 영역으로 계속 보여줍니다.

예:

- 전선 — 필요 0 / 보유 8 / 정리 가능 8
- 볼트 — 필요 6 / 보유 10 / 정리 가능 4

이 목록은 사용자가 실제 보유량을 수정하여 초과가 없어질 때까지 계속 유지됩니다.

따라서 별도의 '알림을 확인했으니 숨김' 상태를 진실의 원천으로 만들 필요가 없습니다.

`보유량 > 필요량`이라는 실제 상태가 해결 조건입니다.

## 7. 변화 알림

필요량 재계산으로 초과 보유 상태가 새로 생기면 사용자가 인지할 수 있어야 합니다.

대표 원인:

- 게임 데이터 업데이트 후 요구 아이템/수량이 감소 또는 삭제됨
- 퀘스트 완료
- 분기 확정으로 다른 경로가 수행 불가능해짐
- 은신처 진행으로 기존 재료가 더 이상 필요하지 않음

UI는 예를 들어 다음과 같이 알릴 수 있습니다.

> 정리할 수 있는 보유 아이템이 생겼습니다.

그리고 사용자는 Item 탭의 `정리 필요` 목록에서 실제 항목을 확인합니다.

알림 자체보다 **정리 필요 목록이 지속적인 진실의 원천**입니다.

## 8. 요구량 변화의 원인을 잃지 않는다

필요 아이템 계산은 Item ID별 총합만 만들고 출처를 버리지 않습니다.

각 요구량은 최소한 다음 출처를 추적할 수 있어야 합니다.

- Quest ID / 요구 objective
- Hideout station / target level

따라서 요구량이 줄었을 때 어떤 요구가 사라졌는지 설명할 수 있는 구조를 유지합니다.

대형 업데이트 전후 차이를 설명해야 할 경우에도 old/new Game Content와 동일한 사용자 진행 상태를 비교하여 차이를 계산할 수 있어야 합니다.

## 9. 자동 삭제/자동 처분 금지

준현 헬퍼는 다음 행동을 하지 않습니다.

- 필요 없어졌다는 이유로 사용자 보유량 자동 삭제
- 아이템이 게임에서 실제로 판매/버려졌다고 가정
- 퀘스트 완료 시 보유량 자동 차감
- 어떤 대체 제출 아이템을 사용했다고 임의 선택

프로그램은 '더 이상 몇 개를 보관할 필요가 없는지'를 알려주고, 실제 인벤토리 사실은 사용자가 변경합니다.

## 10. FIR / Non-FIR

FIR 요구가 있는 아이템은 단순 총수량만으로 초과량을 계산하면 안 됩니다.

정리 가능량 계산은 기존 FIR fulfillment 규칙과 동일하게 **남겨야 할 FIR 요구량과 총 요구량을 모두 만족하는 범위에서만** 계산해야 합니다.

준현 헬퍼는 사용자가 실제로 필요한 FIR 아이템을 '초과'라고 잘못 표시해서는 안 됩니다.

## 11. 구현 원칙

이 기능 때문에 새로운 복잡한 동기화 시스템을 만들지 않습니다.

기본 계산은 다음 세 사실에서 파생합니다.

`Game Content + User Progress → Future Requirements`

`Future Requirements + Inventory → Needed / Satisfied / Surplus`

Quest 완료, Hideout 레벨 변경, 분기 변화, Game Content 업데이트는 각각 자신의 사실만 변경합니다.

Item 기능이 그 변화들을 직접 구독해 별도 상태를 수동으로 맞추지 않고, 동일한 결정론적 계산을 다시 실행합니다.

## 12. 핵심 제품 약속

준현 헬퍼는 업데이트 후 요구사항이 바뀌었을 때 사용자가 예전 정보를 믿고 모아둔 아이템을 **조용히 잊어버리지 않습니다.**

새 데이터에서 필요량이 줄거나 사라져도 사용자 보유량은 보존하고, 초과 보유량을 명시적으로 보여주어 사용자가 더 이상 쟁여둘 필요가 없다는 사실을 알 수 있게 합니다.
