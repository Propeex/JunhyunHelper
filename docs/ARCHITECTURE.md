# ARCHITECTURE — 기술 설계

이 문서는 제품 요구사항이 충분히 정의된 뒤 **어떻게 구현할지**를 기록합니다.

현재 기술 구조는 의도적으로 확정하지 않습니다.

## 현재 상태

`OPEN — 제품 설계 선행`

아직 다음 항목을 정하지 않았습니다.

- 애플리케이션 형태
- 플랫폼/운영체제 범위
- UI 프레임워크
- 프로그래밍 언어
- 프로세스 구조
- 로컬/원격 데이터 처리 방식
- Tarkov 데이터 공급원
- OCR/화면 인식/오버레이 등 입력 방식 필요 여부
- 저장소/캐시 구조
- 업데이트 방식
- 배포 방식

기존 Tarkov-Helper의 기술 스택을 기본값으로 승계하지 않습니다.

## 아키텍처를 정할 때 필요한 근거

기술 선택은 최소한 다음 제품 요구로 설명할 수 있어야 합니다.

1. 어떤 사용 흐름을 지원하는가
2. 요구되는 반응 속도와 안정성은 무엇인가
3. 어떤 입력/데이터를 받아야 하는가
4. 어떤 출력/상호작용이 필요한가
5. 게임 및 사용자 환경에 어떤 제약이 있는가
6. 데이터가 얼마나 자주 변하는가
7. 어떤 실패를 안전하게 처리해야 하는가
8. 유지보수와 자동 검증을 어떻게 할 것인가

## 금지되는 설계 방식

- 기존 구현이 그렇게 되어 있다는 이유만으로 구조 채택
- 요구사항 없이 프레임워크부터 확정
- 제품 동작과 연결되지 않는 과도한 추상화
- 출처/갱신 규칙이 불명확한 게임 데이터 의존
- 테스트할 수 없는 핵심 판단 로직
