# STATE — 현재 프로젝트 상태

> 이 문서는 새 개발자가 가장 빠르게 현재 상태를 복구하기 위한 핸드오프 문서입니다.

## 현재 Phase

**Phase 1 — 제품 발견(Product Discovery) 및 의도 정렬**

상태: `IN PROGRESS`

Phase 0의 프로젝트 기억/개발 운영 구조는 완료되었습니다. 제품 코드는 아직 작성하지 않습니다.

## 프로젝트 이름

**준현 헬퍼**

저장소: `Propeex/JunhyunHelper`

## 프로젝트 목표

새로운 준현 헬퍼를 사용자와의 대화를 통해 **처음부터 제품 설계**하고, 이후 개발자가 바뀌거나 대화가 바뀌어도 저장소만으로 맥락을 복구하여 동일한 방향으로 개발을 이어갈 수 있게 합니다.

## 현재 확정된 핵심 원칙

- `CONFIRMED` 공식 제품명은 **준현 헬퍼**입니다.
- `CONFIRMED` 새 준현 헬퍼는 처음부터 제품 설계합니다.
- `CONFIRMED` 기존 `Propeex/Tarkov-Helper`는 필요할 때만 참고합니다.
- `CONFIRMED` 기존 구현을 정답이나 제품 사양으로 간주하지 않습니다.
- `CONFIRMED` 사용자는 제품 의도와 피드백을 구두로 전달할 수 있으며, 개발자가 이를 구조화하고 구현합니다.
- `CONFIRMED` 사용자의 짧은 기능 설명을 곧바로 완성된 제품 요구사항으로 간주하지 않습니다.
- `CONFIRMED` 개발자는 자신이 이해한 의도를 사용자에게 다시 설명하고 교정받은 뒤 세부 작동 방식을 협의합니다.
- `CONFIRMED` 의미와 동작이 맞은 내용만 공식 요구사항으로 확정합니다.
- `CONFIRMED` 대화 간 연속성은 GitHub 저장소의 공식 문서와 변경 이력을 통해 유지합니다.
- `CONFIRMED` 제품 설계가 충분히 진행되기 전에는 제품 코드 구현을 시작하지 않습니다.

## 현재 전달받은 기능 영역

아래는 **사용자가 말한 초기 방향을 보존한 것**이며 세부 제품 동작이 확정됐다는 뜻이 아닙니다.

1. `INTENT_CAPTURED` **퀘스트 목록** — 조건에 맞는 퀘스트 목록을 보여주고 사용자가 완료 처리할 수 있음
2. `INTENT_CAPTURED` **은신처 목록** — 시설 목록을 보여주고 사용자가 시설 레벨을 설정할 수 있음
3. `INTENT_CAPTURED` **필요 아이템** — 퀘스트/은신처 업그레이드 필요 아이템을 다루며 사용자가 보유 개수를 추가할 수 있음
4. `INTENT_CAPTURED` **탄약 표** — 구경별 탄약과 탄약 정보·수급처 등을 표로 확인
5. `INTENT_CAPTURED` **지도** — 지도에서 각종 정보를 확인하고 미니맵 형태로 인게임 중 사용
6. `INTENT_CAPTURED / LATER` **RatScanner 기능 통합** — 기능을 준현 헬퍼에 옮길 예정이나 현재 원본이 먹통이어서 후속 단계로 둠

## 아직 확정하지 않은 주요 내용

현재 기능 이름과 짧은 설명을 제외하면 대부분의 실제 제품 동작은 아직 설계 중입니다.

특히 다음을 아직 임의로 확정하지 않습니다.

- 각 기능을 언제 어떤 상황에서 쓰는지
- 각 화면에서 실제로 어떤 정보를 보여주는지
- 사용자가 무엇을 클릭/입력/선택하는지
- 프로그램이 자동으로 판단·계산할 내용
- 기능 간 자동 연동 방식
- 데이터 저장/복구 방식
- 예외 상황과 수정 방식
- 정보 밀도, 정렬, 필터, 검색 등 UX 세부사항
- 데이터 소스 선정 및 갱신 방식
- 기술 스택과 아키텍처

## 바로 다음 행동

1. 먼저 개발자가 현재 이해한 **준현 헬퍼 전체의 역할과 각 기능의 의미**를 사용자에게 설명합니다.
2. 사용자가 잘못 이해된 부분, 빠진 부분, 중요한 뉘앙스를 교정합니다.
3. 전체 방향이 맞으면 기능을 하나씩 잡아 실제 작동 방식을 대화로 설계합니다.
4. 각 기능에 대해 목적, 사용 상황, 입력, 화면 출력, 자동 처리, 다른 기능과의 관계, 예외를 정리합니다.
5. 사용자와 의미와 동작이 맞은 내용만 `docs/PRODUCT.md`의 공식 Flow/Requirement로 확정합니다.
6. 제품 요구가 충분히 정의되기 전에는 기술 스택이나 구현 구조를 확정하지 않습니다.

## 현재 열린 핵심 질문

**개발자가 현재 이해한 준현 헬퍼의 전체 그림이 사용자의 의도와 맞는가?**

이 확인이 끝나기 전에는 세부 자동 연동 규칙부터 확정하지 않습니다.
