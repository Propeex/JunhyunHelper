## 프로젝트의 현재 핵심 정의

준현 헬퍼의 핵심은 **최신 Tarkov 데이터를 온라인에서 받아 프로그램 스스로 내부 데이터베이스로 변환·재구축하고, 그 데이터를 게임 진행 상태와 결합해 사용하는 것**입니다.

가장 중요한 유지보수 원칙:

`새 패치 데이터 → GPT가 다시 해석 → 수작업 데이터 갱신`

이 구조를 만들지 않습니다.

목표 구조:

`GPT/개발자가 변환 규칙 구현 → 프로그램이 최신 데이터 다운로드 → 검증 → 변환 → DB 재구축 → 기능이 최신 DB 사용`

일반적인 데이터 업데이트에는 GPT가 필요하지 않아야 합니다.

## 현재 핵심 기능 범위

### 1. API 기반 데이터베이스 업데이트

`CONFIRMED`

현재 핵심 데이터 영역:

- 퀘스트
- 은신처
- 탄약

퀘스트 데이터는 `json.tarkov.dev`를 원천으로 사용하기로 확정했습니다.
은신처와 탄약의 정확한 공급원/엔드포인트는 구현 전 최신 상태를 검증합니다.

지도는 아직 적절한 API 공급원을 확보하지 않아 현재 확정 데이터 파이프라인 밖입니다.

### 2. 퀘스트

`CONFIRMED / 큰 틀 확보`

- 게임 모드별 캐릭터는 서로 독립된 진행 프로필입니다.
- 현재 프로필이 선행 조건을 만족한 미완료 퀘스트를 계산해 보여줍니다.
- 수주 가능한 퀘스트는 준현 헬퍼에서 이미 수락된 것으로 간주합니다.
- 사용자가 완료 처리하면 후속 퀘스트 판정을 갱신합니다.
- 장소/상인 기준 분류와 상세 정보/Wiki 접근을 지원합니다.
- 시간 지연 해금은 판정에서 제외합니다.
- 시각적 UI와 세부 예외 처리는 후속 설계로 미룹니다.

### 3. 은신처

`CONFIRMED / 큰 틀`

- 최신 은신처 데이터를 내부 DB로 변환해 사용합니다.
- 사용자 진행 상태와 결합합니다.
- 은신처 업그레이드 요구 아이템은 필요 아이템 계산의 원천이 됩니다.
- 세부 입력 방식과 UI는 아직 정하지 않습니다.

### 4. 탄약

`CONFIRMED / 큰 틀`

- 최신 탄약 데이터를 내부 DB로 변환해 사용합니다.
- 구경별 탄약과 정보/수급처 등을 제공하는 것이 핵심입니다.
- 세부 표시 방식은 아직 정하지 않습니다.

### 5. 필요 아이템

`CONFIRMED / 큰 틀`

별도 수작업 고정 데이터가 아닙니다.

`최신 퀘스트 요구 아이템 + 최신 은신처 업그레이드 요구 아이템 → 필요 아이템 목록`

퀘스트/은신처 데이터가 패치로 바뀌면 필요 아이템도 같은 데이터에서 다시 계산되어 최신화되어야 합니다.

## 데이터 아키텍처 핵심 원칙

`CONFIRMED`

기본 흐름:

`외부 API → 다운로드 → 스키마/필수 필드 검증 → 내부 모델 변환 → 로컬 DB 구축/갱신 → 기능 사용`

- 제품 로직/UI는 외부 원본 JSON 스키마를 직접 사용하지 않습니다.
- 퀘스트/은신처/탄약마다 변환 계층을 둡니다.
- 데이터 값/내용 변화는 자동 업데이트 대상으로 봅니다.
- 외부 API 형식이 영원히 고정된다고 가정하지 않습니다.
- 비호환 스키마 변경은 감지하고 잘못된 새 DB로 덮어쓰지 않습니다.
- 가능한 경우 마지막 정상 DB를 유지합니다.
