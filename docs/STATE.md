# STATE — 현재 프로젝트 상태

> 이 문서는 새 개발자가 가장 빠르게 현재 상태를 복구하기 위한 핸드오프 문서입니다.

## 현재 Phase

**Phase 1 — 제품 발견(Product Discovery) 및 요구사항 설계**

상태: `IN PROGRESS`

Phase 0의 프로젝트 기억/개발 운영 구조는 완료되었습니다. 제품 코드는 아직 작성하지 않습니다.

## 프로젝트 이름

**준현 헬퍼**

저장소: `Propeex/JunhyunHelper`

## 프로젝트 목표

새로운 준현 헬퍼를 사용자와의 대화를 통해 **처음부터 제품 설계**하고, 이후 개발자가 바뀌거나 대화가 바뀌어도 저장소만으로 맥락을 복구하여 동일한 방향으로 개발을 이어갈 수 있게 합니다.

## 현재 확정된 핵심 원칙

- `CONFIRMED` 공식 제품명은 **준현 헬퍼**입니다.
- `CONFIRMED` 새 준현 헬퍼는 처음부터 제품 설계합니다.
- `CONFIRMED` 기존 `Propeex/Tarkov-Helper`는 필요할 때만 참고합니다.
- `CONFIRMED` 기존 구현을 정답이나 제품 사양으로 간주하지 않습니다.
- `CONFIRMED` 사용자는 제품 의도와 피드백을 전달하고, 개발 세부 절차는 개발자가 담당합니다.
- `CONFIRMED` 대화 간 연속성은 GitHub 저장소의 공식 문서와 변경 이력을 통해 유지합니다.
- `CONFIRMED` 제품 설계가 충분히 진행되기 전에는 제품 코드 구현을 시작하지 않습니다.

## 현재 확정된 상위 기능 범위

1. `CONFIRMED` **퀘스트 목록** — 조건에 맞는 퀘스트 목록 표시 및 사용자 완료 처리
2. `CONFIRMED` **은신처 목록** — 은신처 시설 목록 표시 및 시설별 레벨 설정
3. `CONFIRMED` **필요 아이템** — 퀘스트/은신처 업그레이드 필요 아이템 표시 및 사용자 보유 개수 기록
4. `CONFIRMED` **탄약 표** — 구경별 탄약, 탄약 정보, 수급처 표 조회
5. `CONFIRMED` **지도** — 각종 지도 정보 조회 및 인게임 중 사용할 수 있는 미니맵 형태 표시
6. `PLANNED` **랫스캐너 통합** — RatScanner 기능을 준현 헬퍼로 옮길 예정. 현재 원본 프로그램이 정상 동작하지 않아 후속 단계로 보류

세부 동작은 `docs/PRODUCT.md`를 기준으로 하며, 확정되지 않은 연동 규칙은 기존 구현에서 추정하지 않습니다.

- `docs/DECISIONS.md` — 확정 결정 이력

## 아직 확정하지 않은 주요 내용

- 퀘스트 목록의 조건/필터/정렬 방식
- 퀘스트 완료 상태와 필요 아이템의 자동 연동 규칙
- 은신처 시설 레벨과 향후 필요 아이템 계산 규칙
- 동일 아이템이 여러 목적에 필요할 때 합산 방식
- 아이템 보유 수량과 필요 수량의 차감/부족 수량 표시 방식
- 탄약 표의 정확한 정보 컬럼과 정렬/필터 UX
- 지도에 표시할 정보 종류와 미니맵 창 동작
- 사용자 진행 상태 저장/복구 방식
- RatScanner 이식 범위와 기술적 가능성
- 데이터 소스 선정 및 갱신 방식
- 기술 스택과 아키텍처

## 바로 다음 행동

1. 서로 직접 연결되는 `퀘스트 목록 ↔ 은신처 목록 ↔ 필요 아이템`의 진행 상태 및 계산 규칙을 사용자와 정의합니다.
2. 이후 탄약 표와 지도 각각의 실제 사용 흐름과 표시 정보를 정의합니다.
3. RatScanner는 현재 핵심 설계를 방해하지 않도록 후속 조사 대상으로 유지합니다.
4. 제품 요구가 충분히 정의되기 전에는 기술 스택이나 구현 구조를 확정하지 않습니다.

## 현재 열린 핵심 질문

- `OPEN` 퀘스트를 완료 처리하면 그 퀘스트에 필요한 아이템은 필요 아이템 목록에서 어떻게 처리해야 하는가?
- `OPEN` 은신처 시설 레벨을 설정하면 어느 레벨 이후의 업그레이드 필요 아이템을 보여줘야 하는가?
- `OPEN` 사용자가 입력한 아이템 보유 개수는 총 필요량에서 차감하여 부족 수량을 보여줘야 하는가?
