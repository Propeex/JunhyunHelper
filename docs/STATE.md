# STATE — 현재 프로젝트 상태

> 이 문서는 새 개발자가 가장 빠르게 현재 상태를 복구하기 위한 핸드오프 문서입니다.

## 현재 Phase

**Phase 1 — 제품 발견(Product Discovery) 및 의도 정렬**

상태: `IN PROGRESS`

Phase 0의 프로젝트 기억/개발 운영 구조는 완료되었습니다. 제품 코드는 아직 작성하지 않습니다.

## 프로젝트 이름

**준현 헬퍼**

저장소: `Propeex/JunhyunHelper`

## 프로젝트 목표

새로운 준현 헬퍼를 사용자와의 대화를 통해 **처음부터 제품 설계**하고, 이후 개발자가 바뀌거나 대화가 바뀌어도 저장소만으로 맥락을 복구하여 동일한 방향으로 개발을 이어갈 수 있게 합니다.

## 현재 확정된 핵심 원칙

- `CONFIRMED` 공식 제품명은 **준현 헬퍼**입니다.
- `CONFIRMED` 새 준현 헬퍼는 처음부터 제품 설계합니다.
- `CONFIRMED` 기존 `Propeex/Tarkov-Helper`는 필요할 때만 참고합니다.
- `CONFIRMED` 기존 구현을 정답이나 제품 사양으로 간주하지 않습니다.
- `CONFIRMED` 사용자는 제품 의도와 피드백을 구두로 전달할 수 있으며, 개발자가 이를 구조화하고 구현합니다.
- `CONFIRMED` 사용자의 짧은 기능 설명을 곧바로 완성된 제품 요구사항으로 간주하지 않습니다.
- `CONFIRMED` 개발자는 자신이 이해한 의도를 사용자에게 다시 설명하고 교정받은 뒤 세부 작동 방식을 협의합니다.
- `CONFIRMED` 의미와 동작이 맞은 내용만 공식 요구사항으로 확정합니다.
- `CONFIRMED` 대화 간 연속성은 GitHub 저장소의 공식 문서와 변경 이력을 통해 유지합니다.
- `CONFIRMED` 제품 설계가 충분히 진행되기 전에는 제품 코드 구현을 시작하지 않습니다.

## 현재 전달받은 기능 영역

1. `CONFIRMED / 설계 진행 중` **퀘스트 목록**
2. `INTENT_CAPTURED` **은신처 목록**
3. `INTENT_CAPTURED` **필요 아이템**
4. `INTENT_CAPTURED` **탄약 표**
5. `INTENT_CAPTURED` **지도**
6. `INTENT_CAPTURED / LATER` **RatScanner 기능 통합**

## 퀘스트 기능 — 현재 확정된 설계

- `CONFIRMED` 최신 퀘스트 원천 데이터는 `json.tarkov.dev`에서 받고 준현 헬퍼 내부 모델로 변환합니다.
- `CONFIRMED` 전체 퀘스트 중 사용자의 현재 프로필과 완료 상태를 기준으로 실제 게임에서 수주 가능한 미완료 퀘스트를 계산합니다.
- `CONFIRMED` 실제 게임의 `잠김 → 수주 가능 → 진행 중` 중 준현 헬퍼는 수주 가능한 퀘스트를 사용자가 모두 수락한다고 가정합니다.
- `CONFIRMED` 준현 헬퍼의 핵심 상태는 `잠김 → 현재 퀘스트 → 완료`입니다.
- `CONFIRMED` 사용자가 게임에서 퀘스트를 완료하면 준현 헬퍼에서도 완료 처리하고, 후속 퀘스트 해금 판정을 다시 계산합니다.
- `CONFIRMED` 사용자 프로필에 퀘스트 판정에 필요한 상태를 입력·수정할 수 있어야 합니다.
- 현재 명시된 프로필 조건 후보: 레벨, 진영, Fence 우호도, 게임 모드, 게임 에디션, 프레스티지 횟수, 완료 퀘스트.
- `CONFIRMED` 퀘스트 목록은 장소(맵) 또는 상인 기준으로 분류해서 볼 수 있어야 합니다.
- `CONFIRMED` 퀘스트를 선택하면 설명/목표 등 클리어에 필요한 정보와 Wiki 페이지를 확인할 수 있어야 합니다.

## 아직 확정하지 않은 주요 내용

- `json.tarkov.dev`의 모든 퀘스트 선행 조건 유형과 실제 데이터 표현
- 사용자 프로필의 최종 필드 목록과 입력 UX

- 퀘스트 상세 화면의 정보 우선순위
